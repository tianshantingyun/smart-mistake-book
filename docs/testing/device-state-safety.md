# 设备测试的数据保护（2026-10-15）

本机本项目的 `connected...AndroidTest` 执行后，曾出现被测应用及其私有数据目录被测试框架清理的情况。测试开始前包已安装、安装命令使用覆盖安装，都不能作为数据会保留的证据。

## 执行前

1. 优先使用可丢弃、专用于自动化测试的模拟器，并核对 adb serial、应用包名、AVD 名称。
2. 共享或已有数据的设备，先将数据库、题图和所需配置备份到设备之外，验证备份确实可读，记录恢复步骤。
3. API Key 与 Keystore 内容不在应用的完整备份中；不能只凭 `.smbk` 就承诺连模型凭证一起恢复。
4. 无可验证备份时，改用隔离的测试设备。检查测试夹具是否还会清库或注入学习记录。

## 执行后

1. 检查被测包是否仍安装，数据目录和实际题目是否还在。
2. 有备份时按记录恢复并核对题图、题数和历史记录；没有备份时如实报告影响，不能用合成记录冒充原始学习事实。
3. 设备测试的结果应注明使用真实数据还是注入夹具，UI 测试成功不等同于原始现场数据仍完整。

本次事件与用户选择见 [补修记录](../research/2026-10-15-user-visible-fixes.md)。

## 证据格式

本文件只负责设备数据保护（备份、真实数据、测试后检查）。设备结论的落点、模板、体量上限、脱敏扫描与引用格式见 [设备验证证据落盘规范](../research/2026-10-26-device-evidence-convention.md)（v1，批次 23 起生效）；两者同时适用。
