## 3. C-6 快照身份：内容身份 = db + wal，`-shm` 显式排除

### 3.1 落点与旧文

- 落点：`docs/current/visual-generation-contract.md` **`:208` 段尾**（AUD-08 长行内），替换下列旧句（本轮 `sed -n '208p'` 实读，逐字）：

> **快照身份边界（2026-10-29 批次 32 T6 登记 KD-81）**：`export_split_eval.py` 的 `source.db.sha256` 只覆盖主库文件字节（`_sha256` 在 `:72-73`、manifest 在 `:221-222`），**不含 `-wal`/`-shm`**；设备库默认 WAL 模式，同一主库 + 不同 WAL 会得到不同导出却报同一 sha（受控实验见 `tools/split_golden/README.md:86-89`）。取库/复现必须三件同一时刻保存并比对，或先显式 checkpoint 并校验完成；未覆盖前，该 sha 只能读作"主库字节摘要"，不得读作完整快照身份。

该句与 KD-81 的关闭裁定（批次 35：db + wal 进身份、`-shm` 排除）矛盾，且工具已按裁定实现；句子本身是"未覆盖前"的历史时点表述。

### 3.2 拟并入文本（替换上述整段）

> **快照身份（V1.1 C-6，KD-81 关闭口径）.** "快照身份"指导出输入字节清单的摘要，输入 = **主库文件 + `-wal`**；`-shm` 是只读导出会重建/改写的共享内存索引，**显式排除**，不得纳入身份，也不得写进产物。身份必须在导出前记录、导出后复核；导出期间 db/-wal 字节发生变化必须拒绝，且拒绝先于写盘失败。身份只证明"输入字节一致"，**不证明 SQLite 读事务实际读到的逻辑快照**；后者需要读事务钉住（`READ_TRANSACTION_DOCUMENTATION`），不得由身份摘要冒充。空 `-wal` 按"无 WAL"归一（只读打开 WAL 库会自建 0 字节 `-wal`）。

### 3.3 消灭的失败

1. 同主库不同 WAL 报同一身份（旧 `source.db.sha256` 单文件摘要）。
2. `-shm` 自指漂移（导出自身改写 `-shm`，若纳入身份则每次导出换身份）。
3. 把字节身份宣传成事务级快照。

### 3.4 判据（工具已实现，并入时应原样保留）

- `tools/split_golden/export_split_eval.py:28-36`：`identityKind = inputs-v1`，`sha256(canon({db, wal}))`；`-shm` 不收、不输出。
- 同一快照复跑输出逐字节一致（无时间戳、不记 mtime、不记 `-shm`）。
- 导出期间 db/-wal 变化 → exit 2（`快照一致性`），且先于写盘。
- 并入后：契约正文不得再出现"不含 `-wal`"的快照身份表述（`grep -n "不含 \`-wal\`" docs/current/` 应为 0）。
