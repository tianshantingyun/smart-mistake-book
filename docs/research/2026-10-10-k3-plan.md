## 2. 设计（每项指认它消灭的失败）

### 批 1 · KF-30 落地
1. **加列** `accepted_confidence`（nullable REAL）：实体 + 记录 + 两映射 + 定串。
   → 消灭：**存量行置信度被伪造为门值**（`:943-944`），它是 KF-30 (a)(b) 的共同根因。
2. **迁移 63→64**（非破坏、纯加列、旧行 NULL、幂等）+ 导出 `64.json` + `KernelWave0SchemaContractTest` 同步。
   → 消灭：实体与 schema 不一致（旧库打不开/写入抛错）。
3. **写侧**：自动路径写**真实分数**（`:1023` 已有）；用户/离线路径无模型分数 → 写 **NULL**（权威由
   `acceptanceSource` 表达，保护语义不变）。
   → 消灭：真实置信度不落库 → 合并只能猜。
4. **合并侧读真值**：存量自动行读列值参与排序；**NULL 按门值处理**（裁定 Q2 interim：未知 ⇒ 任何
   严格更高且 ≥门值的新提议可替换它，**不冻结**——用户否掉"只能用户改")。
   → 消灭：(b) 的 0.79-顶-0.99；以及"旧行成死水"。
5. **测试（全部非恒真）**：① 存量 0.99 + 新提议 0.79 → 保留存量（改前会替换 ⇒ 能红）；② 等值 0.80 vs 0.80
   → 保留存量；③ 存量 NULL + 0.80 提议 → 被替换并写真实分数（**系统自纠路径**）；④ 用户/离线保护语义不变
   （既有用例语义不改）；⑤ 迁移后旧行 `accepted_confidence IS NULL` 且幂等；⑥ `sameAcceptedFact` / 命令指纹
   是否纳入该值的**决定 + 用例**（实施期定并写进记录与 KDoc）。
6. **版本口径**：**默认零算法 bump**——判据「既有账本的重放输出不因本改动而变化」（本改动不触碰 `core:domain`
   投影/归因/伪桶路径；既有重放指纹与 pseudo 用例须全绿）。实测有变 → 停上升级，按台账纪律评估 bump。
