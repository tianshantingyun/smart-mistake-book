# 4E WG-06/07/08 设计件：类型化视觉引用、导出角色与 schema 69

> 状态：2026-10-21 批次 16 **设计件**，不包含实现。批次 16 的 T8 子代理因提供方错误未完成，本文由主会话据 4E 研究结论落盘。

- WG-01 公共装配/协调器/派发账本已落地；WG-05 历史 attachedImages 已收口（cache-only + 显式重生成）。
- 协调器只执行 `IMAGE_MODEL`；`JS` 返回 `UNAVAILABLE` 且不广告。
- 请求 schema 已到 18（批次 16 T3：`TutorVisualContext`、工具 method/program/imageOperation/imagePrompt）；DB schema **68**，无 `69.json`。
- 批次 16 T1a 的 PRD-05 attempt undo 使用无 schema VOID 哨兵，`schemaVersion=68`；因此 **schema 69 留给 4E WG-08**。
- 旧链：讲题 REDRAW 可挂 `CLEAN_IMAGE`；`MistakePdfEligibility` 只认 `CLEAN_IMAGE`；DOCX 只读本地文件；详情没有显式重绘命令。
- 缺口：没有 operation/attempt 持久表、没有消息/题目 revision 的类型化视觉引用、没有角色过滤、没有导出/恢复闭包。

## 2. 数据模型（schema 69，非破坏迁移）

所有表只追加，不改旧行；`created_at_epoch_millis` 与 `operation_id/attempt_id` 为审计锚点。

### 2.1 `figure_generation_operation`
- `operation_id` TEXT PK（内容寻址：basis + purpose + slot；**不含 method**，见提示词策略 §99-103）
- `learner_id`、`source_kind`（TUTOR_MESSAGE / PROBLEM_REVISION / CLEAN_REDRAW / CAPTURE_PARSE）、`source_id`
- `basis_fingerprint`（修订/题面/源图 sha 的组合，冻结输入）
- `purpose`（SOURCE_RECONSTRUCTION / QUESTION_DIAGRAM / EXPLANATION / CLEAN_REDRAW）
- `policy_version`、`status`（PENDING/RUNNING/SUCCEEDED/FAILED/SUPERSEDED/CANCELLED）
- `reserved_remote_dispatches`、`used_remote_dispatches`、`final_answer_reserved`
- `created_at_epoch_millis`、`updated_at_epoch_millis`

### 2.2 `figure_generation_attempt`
- `attempt_id` TEXT PK（含 method，见策略 §99-103）
- `operation_id` FK → operation
- `method`（IMAGE_MODEL / JS；当前只写 IMAGE_MODEL）
- `status`、`provider_snapshot`、`model_snapshot`、`source_sha256`
- `output_asset_id`（nullable；失败为空）、`diagnostics`（有界文本）
- `started_at_epoch_millis`、`ended_at_epoch_millis`
- 唯一约束：`(operation_id, attempt_id)`；终态 attempt 不得复活。

### 2.3 JS 程序/快照（为 4E.2/4E.3 预留，本批不写入）
- `tutor_visual_program(program_id PK, operation_id, source_js, sdk_version, capability_version, state_json, diagnostics, program_hash)`
- `tutor_visual_snapshot(snapshot_id PK, operation_id, program_id, scene_hash, render_asset_id, created_at)`

### 2.4 类型化引用
- `tutor_message_visual(message_id, visual_id, role, ordinal, basis_revision_id)`
- `problem_revision_visual(problem_revision_id, visual_id, role, basis_revision_id)`
- `visual_id` 指向 operation/attempt 的产物（canonical asset + 角色），**不把文件路径写进题面块**。
- 角色：`QUESTION_DIAGRAM`（题目图）、`TUTOR_EXPLANATION`（讲解图）、`CLEAN_IMAGE`（题面净化图）、`SOURCE_EVIDENCE`（源图证据）。
- `clean_redraw_task` 非破坏性加 `operation_id`（nullable）；旧行保持可用。

## 3. WG-06：保存、详情与重绘出口

- 保存：`saveTutorSession` 在同事务写 `problem_revision_visual`/`tutor_message_visual`；引用 operation/attempt 的终态成功产物，不复制文件。
- 详情：按当前 revision + role 读取；历史 revision 读其冻结的 visual refs；打开/展开/旋转只读本地资产，**0 模型派发**。
- 显式重绘命令：`RedrawProblemVisualCommand(problemRevisionId, expectedRevisionId, role, reason)`；创建 operation、预留预算、异步执行；UI 显示进行中/失败/可重试。
- 晚到结果：写入前校验 `expectedRevisionId` 与 basis；旧 revision 的结果标 `SUPERSEDED`，不覆盖新 revision。
- 讲解图：按 `includeSolution`/角色隔离到解析区；题目区默认不含讲解图/答案图。
- 失败：缺源、损坏、预算耗尽、取消分别有可读 diagnostics；不静默少图。

## 4. WG-07：PDF/DOCX/打印/分享

- 导出输入从 `CLEAN_IMAGE` 硬编码改为**类型化 visual refs**；按角色与 `includeSolution` 过滤。
- PDF/DOCX 消费同一份 canonical 资产；DOCX 嵌入真实 PNG；打印/分享复用既有交付链。
- 导出 **0 模型派发**；必图缺失时 fail-closed 并报出缺哪一类图，不导出无图假成功。
- 未编辑/未重绘的导出与旧链逐位一致；编辑只改文档副本，不反写原题。

## 5. WG-08：迁移、恢复与备份闭包

- 68→69 非破坏迁移：新表 + `clean_redraw_task.operation_id`；`69.json` 由 KSP 生成；矩阵测试 1→69。
- 备份：manifest 引用 operation/attempt/visual refs 与 canonical assets；恢复时校验资产引用闭合；缺资产按 AUD-05 在交换前拒绝。
- GC：被 visual refs/题目 revision/消息引用的资产必须 pin；未引用资产才可清理。
- 冷恢复/杀进程：operation/attempt 终态可恢复；RUNNING 超时转 FAILED/待核实；不重复付费。
- 恢复后详情/导出与恢复前一致；旧包（68）恢复后迁移到 69。

## 6. 验收矩阵（下一批实施时执行）

1. IMAGE_MODEL：生成 → 保存 → 杀进程 → 重开 → 详情可见 → PDF/DOCX 有图 → 打开/导出 0 派发。
2. 重绘：显式重绘 → 进行中/成功/失败；旧 revision 结果 `SUPERSEDED`；新 revision 不被污染。
3. 角色：题目区不含讲解图；`includeSolution` 控制解析区；缺失必图 fail-closed。
4. 迁移：1→69 全路径；68→69 旧行保行；备份/恢复 ≥365MB（含 visual）往返。
5. 资产：缺资产交换前拒绝；损坏/哈希不符不静默；GC 不删被引用资产。
6. JS：仅在 QuickJS 工程门与 PRD-09 质量门通过后加入 `availableMethods`；此前不广告、不执行、不假成功。
7. 真实 Provider：记录模型/参数/token/派发/成功率；无凭据记 UNVERIFIED。
