## 三、预检②结构性不可满足的机制证据（本会话新证，修正批次 36 R1 模型）

### 3.1 两 mapping 均含 `# L8 Desugaring Mapping` 段——j$ 改名全部出自 L8 编译

```bash
grep -n "# L8 Desugaring Mapping" app/build/outputs/mapping/strictOfflineReleaseAndroidTest/mapping.txt   # :39430
grep -n "# L8 Desugaring Mapping" app/build/outputs/mapping/strictOfflineRelease/mapping.txt              # :860808
```

两条碰撞行都在该段内（测 `:49037` > 39430；主 `:871645` > 860808）。即：**mapping.txt 中全部 j$ 条目（含改名、含 `R8$$REMOVED$$CLASS$$N`）是 L8（desugared library）编译的产物映射**，由 AGP 合并进 mapping.txt（AGP 9.1+ 行为；外部印证见 §六.2/§六.7）。

### 3.2 j$ 恒等集与"生成式 L8 keep 规则"逐一对应（决定性对照）

本会话 awk 实测（`awk -F' -> ' '/^j\$/{split($2,a,":"); if($1==a[1]) id++; else if(a[1]!~/REMOVED/) ren++; else rem++}'`）：

| mapping | j$ 条目 | 真恒等 | 真改名（非 REMOVED） | REMOVED |
|---|---:|---:|---:|---:|
| 主（strictOfflineRelease） | 548 | **40** | 465 | 43 |
| 测（strictOfflineReleaseAndroidTest） | 527 | **6** | **476** | 45 |

- **测试侧恒等的 6 个**：`j$.time.Clock`、`j$.time.Instant`、`j$.time.ZoneId`、`j$.util.Objects`、`j$.util.concurrent.ConcurrentHashMap`、`j$.util.function.Consumer$-CC`。
- **AGP 生成的该变体 L8 keep 规则**（`app/build/intermediates/desugar_lib_keep_rules/strictOfflineReleaseAndroidTest/l8DexDesugarLibStrictOfflineReleaseAndroidTest/keep_rules.txt`，本会话实读全文）恰好 **7 条** `-keep`：上述 6 类（各带被引用的成员签名）+ `-keep interface java.util.function.Consumer {}`。**与恒等集逐一对应。**
- **主包侧同构**：`…/strictOfflineRelease/l8DexDesugarLibStrictOfflineRelease/keep_rules.txt` 52 条 `-keep`，含 `-keep class j$.util.DesugarCollections { public static java.util.Map synchronizedMap(java.util.Map); }` 等 → 对应主 mapping 40 个恒等类（`j$.util.DesugarCollections` 在主包恒等、在测试包改名 `j$.util.i`，两变体生成规则不同所致）。
- **用户 keep 的对照**：`-keep class j$.** { *; }` 在测试 R8Task 配置在场（`mapping/strictOfflineReleaseAndroidTest/configuration.txt:75`）却对 476 个改名**零效果** → 该规则不在决定 j$ 改名的配置面上。
- 主/测两套改名各自从 `j$.util.a/b/c…` 起分配短名（`-keeppackagenames j$.**` 保证改名留在 j$ 命名空间）→ 短名池天然大量重叠，碰撞是**结构性**的，不止 `j$/util/g` 一点（§四.3 选项分析）。

### 3.3 desugar_jdk_libs_configuration 2.0.3 的 desugar.json（Gradle 缓存实读）

```text
META-INF/desugar/d8/desugar.json:
  synthesized_library_classes_package_prefix = "j$/"
  shrinker_config（全文）= -keepclassmembers class j$.** extends java.io.Serializable {…序列化成员…}
                          -keepclassmembers class j$.util.concurrent.ConcurrentHashMap$TreeBin { int lockState; }
                          -keepclassmembers class j$.util.concurrent.ConcurrentHashMap { int sizeCtl; … }
                          -keepclassmembers enum * { values(); valueOf(…); … }
                          -keeppackagenames java.**
                          -keeppackagenames j$.**
                          -keepclassmembers class j$.util.{Int,Long,Double}SummaryStatistics { … }
                          -keepattributes Signature / EnclosingMethod / InnerClasses
                          -dontwarn sun.misc.Unsafe / -dontwarn wrapper.**
```

**关键**：`shrinker_config` 只含 `keepclassmembers`（成员保活）与 `-keeppackagenames`（包名不变），**没有任何保类名的 `-keep class j$.**`**——L8 阶段对未被生成式规则保住的 j$ 类一律改名。L8 任务的规则输入 = 该 `shrinker_config` + AGP/R8 生成的每变体 L8 规则（§3.2），**不含用户的 `testProguardFiles`/`proguardFiles`**（生成式规则文件仅 7/52 条，若有用户规则汇入，`j$.**` 全域 keep 必然显现——实测未显现）。

### 3.4 desugar jar 与 L8 dex 中间产物（物理证据）

- `desugar_jdk_libs-2.0.3.jar`（Gradle 缓存）内类在 `java/` 包：`java/util/DesugarCollections.class`、`java/util/Comparators$NaturalOrderComparator.class`、`java/util/DesugarCollections$SynchronizedMap.class` 等，**jar 内 0 个 `j$/` 条目**（`unzip -l | grep -cE 'j\$/'` = 0）→ `j$.*` 前缀是编译期按 `synthesized_library_classes_package_prefix` 合成/改写的产物，不是 jar 原名。
- **每变体独立 L8 dex**：`app/build/intermediates/desugar_lib_dex/<variant>/l8DexDesugarLib<Variant>/classes1000.dex` 对 6 个变体各存一份；本会话实测 `strictOfflineReleaseAndroidTest` 份含 `j$/util/g` 字符串 2 处、`strictOfflineRelease` 份含 1 处——**两 APK 各自带一份独立改名的 L8 dex**，合并进各自 APK 的 classes*.dex。碰撞对（主 L8 的 `j$/util/g`=SynchronizedMap vs 测 L8 的 `j$/util/g`=NaturalOrderComparator）由这两个**独立编译**分别产生。

### 3.5 修正后的机制模型（对批次 36 R1 §4.1 的修正）

| R1 模型（批次 36） | 本会话修正（产物证据 + 外部印证） |
|---|---|
| "主/测两包由两次独立 R8 产出、无改名协调，`j$` 类作为程序输入各自 minify" | j$ 类**不在 R8Task 的改名管辖内**：AGP 管线为 R8（主/测各一次）→ TraceReferences 生成 L8 规则 → **L8 编译**（`l8DexDesugarLib<Variant>` 任务，每变体一次），j$ 改名与收缩全部发生在 L8，L8 mapping 以 `# L8 Desugaring Mapping` 段合并进 mapping.txt（§3.1–3.4；外部：Keeper 文档"the R8 task will generate proguard rules indicating which j$ types are used in source, which the L8DexDesugarLibTask then uses"；rules_android #533 "AGP instead runs an R8 → TraceReferences → L8 pipeline"） |

### 3.6 为什么"非放宽"的预检②重述也救不回来

预检②的语义 = "测试 dex 不占用主包改名产物名"（R1 §4.1 预测的产物化）。在"两 APK 各带独立改名 L8 dex"的架构下：主/测短名池同源（`j$.util.a…`），交集非空是常态（当前产物对中 `j$.util.g` 双侧占用即是），任何不放宽的等价表述（如"主/测 mapping 的 j$ 短名集合无交集"）同样不可满足。**要使②可满足，必须改变产物架构**（测试 APK 不带 L8 dex，或两侧改名协调），均非 `.pro` 规则可达（§五）。

## 五、解锁路径选项（归主会话裁定；GitHub 优先纪律下的评分见 §六）

### 5.1 slackhq/Keeper（结构方案，唯一发现的可落地先例）

Keeper 对本失败类的两个动作（官方文档 `docs/index.md` "Core Library Desugaring (L8) Support" 节，本会话 web_reader 实取原文）：

1. "Keeper merges **generated L8 rules** from both the androidTest and target app to ensure they cover all used APIs. These merged rules are given to the **target app L8DexDesugarLibTask**."——把测试侧需要的 j$ 类并入主包 L8 keep，主包 L8 dex 成为超集；
2. "L8 will still, by default, generate a dex file of backported APIs into **both** the test app and target app, which can cause confusing runtime classpath issues due to L8 generating different implementations in each app. Keeper works around this by **forcing the use of a single dex file in the target app and preventing the inclusion of a backport dex file in the test app**."——测试 APK 不再自带独立改名的 L8 dex，碰撞的物理载体被移除。

代价与风险（主会话裁定项）：**新 Gradle 插件依赖**（Apache-2.0；Maven Central）；Keeper 自述 "**uses private APIs from AGP and could break between releases**"，本仓 AGP **9.3.0**（`gradle/libs.versions.toml:2`）兼容性 **UNVERIFIED**（最新 release 0.16.1 为 2024-06-28，repo pushed 2026-06-02、269★ 未归档——`gh repo view` 本会话实取）；触 `settings.gradle.kts`（**热区禁改**，需解冻裁定）与依赖钉版门（`check_dependency_pins.py`）；另需评估其"androidTest 用法推断 keep"（TraceReferences）对主包混淆面的膨胀影响。

### 5.2 已评估并拒绝/不可达的路径

- **公共 AGP DSL 给 L8 任务喂规则**：本会话 3 轮检索（searchd ×2 + Keeper/AGP 文档路径）未发现任何公共 DSL/属性可向 `l8DexDesugarLib*` 注入用户 keep 规则；Keeper 走私有任务 API 佐证其不存在（"未找到 + 不当事实"，UNVERIFIED）。
- **主包侧对称 keep `j$.**` 进 `proguard-rules.pro`**：与测试侧同理到不了 L8 改名面，且生产 dex 全量膨胀（R1 §4.1 拒绝理由仍成立）。
- **逐类反射引用 hack**（让 TraceReferences 为 `SynchronizedMap` 生成 L8 keep）：碰撓名池重叠是结构性的（§3.2），逐类打补丁属 whack-a-mole；且往生产代码塞测试轨专用引用违反新增纪律。
- **applymapping 改名协调**：AGP 未对 androidTest R8 暴露（R1 已核 build 日志 0 命中；本会话未见反证）。
- **`-dontobfuscate`（任意侧）/ internal 变体**：判据红线，禁止。
