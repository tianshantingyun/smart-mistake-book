## 2. 设计（每项指认它消灭的失败）

### 2a. ④-6：把「索引完整」判定缓存为每进程每科一次
- **消灭的失败**：每次检索/讲题固定多付 ~12.6ms（设备更高；`KnowledgeContextRetrievalInstrumentedTest`
  记录 p50=57ms/p95=81ms 里含它）——纯浪费的预算占用；且这是学生每次讲题都会付的固定成本。
- 改法：以「(subject, INDEX_VERSION)」为 key 的进程内缓存（判定=「已索引数 ≥ 已审校数 或 已审校=0」）；
  三处写路径显式失效：内容安装（`applyKnowledgeContentUpdate`）、整科重建（`KnowledgeSearchIndexBuilder`）、
  只补缺分支自身；缓存命中时召回路径**零 DAO 调用**。
- **不做**：不改召回 SQL、不动排序语义、不动锚点协议（S21 安装期预热的成果保持）。
- 验收：①「不再执行两条 COUNT」用**计数断言**（不是计时）——优先 Room 3.0 `setQueryCallback`
  （实施期先探针确认；不可用则加 internal 计数缝，仅测试可见）；②**负向红样例**：安装新节点后同进程召回
  必须立即可见（失效漏接线即红，先写红样例再改）；③锚点换版整科重建不回归；④`KnowledgeContextRetrievalInstrumentedTest`
  p50/p95 不回归。

### 2b. 50k FTS 规模补测
- **消灭的失败**：「`MATERIALIZE` 一次成本随目录行数线性」只有推断、没有 50k 实测；S18 尾结论的适用范围无界。
- 改法：两个门类夹具参数化到 50k（count：100 命中 / 1 万命中 / **5 万命中**；排序：12 命中 / 宽命中集），
  **记录项不设新门**（沿用 10k 口径：100 命中仍为门），如实记录夹具建库成本与三项计时。
- 验收：50k 三项计时 + 建库成本入报告；100 命中门与既有结构/计数断言不回归。

### 2c. P95 公式并存 → 记录互引（不改公式）
- 两处公式的差异（`(n-1)*95/100` 略严）写进完成记录的风险节并互引；**不动任何公式**（改公式会动
  SECTION facet 边际门松紧，需另裁）。

### 2d. KF-32 空绑定重放 → 改挂 pseudo 兜底
- **消灭的失败**：一道「诚实未分类」（空绑定）的题，其历史证据在重放后**仍挂在旧知识点上**——
  复习以知识点为核心扫描展开时，会把本不属于它的证据算进那个知识点的掌握度（KF-32 只修了非空改绑路径）。
- 语义（本计划定案）：重放时该题当前绑定为空 → 历史证据改挂 `pseudo:<科目>` 兜底桶（复用既有
  `ensurePseudoKnowledgeBinding`），旧知识点状态归零、证据不丢、重放幂等；与写路径逐条同规则。
- 实施面：重放侧 facts 装配与写路径对齐（不新增机制）；`LearningProjector.attributionsForAttempt` 的
  `ifEmpty` 只保留「绑定全被过滤」的异常兜底，不再吞掉空绑定情形；`PracticeUnitBindingAttribution.kt:33-34`
  的注释随之改准确。
- 验收用例：①空绑定 → 重放 → 证据挂 pseudo、旧节点归零；②幂等重放；③改绑（非空）主路径行为不变；
  ④写路径逐位不变；⑤pseudo bindingId 确定性（以 `ensurePseudoKnowledgeBinding` 既有用例为准）。

### 2e. D-5 装机快路径回归钉
- **消灭的失败**：D-5 落账最易踩的静默失效（只写侧车不 bump manifest）目前只有文档警示、无回归钉子。
- 改法：把 `install()` 的「戳一致即跳过」判定抽成 internal 纯函数 + JVM 两态用例（一致 → 跳过；不一致 → 全量）。
  仪器化「只写侧车不 bump → 三元组不到设备」因 `install()` 无 manifest 注入口**不做**，登记。
- 验收：两态用例绿且非恒真（改判定即红）；`BundledKnowledgeBaseInstaller` 行为零变化（纯抽取）。

- 「不再执行 COUNT」的断言手段依赖 Room 3.0 `setQueryCallback` 可用性（未离线核实）→ 实施期探针，回退 internal 计数缝。

- pseudo bindingId 确定性 → 复用 `ensurePseudoKnowledgeBinding`，以其既有用例为准。
- ④-6 探针数字（12.6ms）是桌面 SQLite 探针，设备侧以 p50/p95 复核为准。
