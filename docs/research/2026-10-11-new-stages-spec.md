## 3E · 全库薄弱点扫描（内核侧）【R5-F7】

- **需求**：知识点复习候选范围从"今日错题所绑知识点并集"扩为**全库扫描**（改 spec §1.3/§3.2
  范围定稿）；每日捞回量由 F8 预算 + F17 配额封顶。残留边界（定稿已注）：无绑定题的知识点
  无时间信号，不在本阶段范围。
- **现状证据**：范围锁死见 `StudyReviewPlannerService.kt:541-556`（注释原话"不把整个知识库拖进来"）；
  知识点风险由承载题的最小 FSRS 保留率聚合（`KnowledgeReviewQueue.kt:109-132`）；打分机制完整
  （审-D3），缺的是**第二个范围档**。F17 维护配额 C5 已设计。
- **大致实现方向**：
  1. 候选源加第二档：全库知识点按「掌握度下滑 + 保留率风险」打分（复用 `KnowledgeReviewQueue`
     既有打分），与今日队列并集合并、按分取前 N；
  2. N 由 F8 预算（时间）+ F17 配额（名额）双封顶；
  3. spec §1.3/§3.2 同步改写范围定稿（文档与代码同批，不许只改一处）。
- **关键决策**：第二档捞回量的默认预算/配额**待裁**（起步占位值，Wave X 校准）。
- **验收门**：弱掌握点离开今日错题并集仍可被捞回；F8/F17 封顶生效（主线 3E 行）。

## 4C · 错题本与录入二期【R3 + R11】

- **需求**：A4 整卷自动切题为批量录入主路径（**切分准确率红线：切残题干不得入库**）；A5 连拍；
  A6 文件导入；A7 系统分享进 App；A8 手动建题；B5 题级去重；C11 收藏开关（唯一手动标记，
  复习/组卷可筛）。
- **现状证据**：**2026-10-11 核实：main 树已无 `BatchSplitRecognizer`**（仅存在于另一会话的历史
  worktree，定稿 R3「已建未接」系旧证据）——A4 按**重建切分器**立项；录入已统一为一条流（4A 批 3）；
  材料层有去重、题级无。
- **大致实现方向**：
  1. **新建整卷切分器**接入录入流：整卷图 → 切分 → 逐题走既有单题录入链；
  2. **切分金标集先行**：人工标注一批整卷→题块，定切分准确率门（立项时自定，仿绑定 95% 门；
     定稿明示红线现无量化门）——**门不过不准自动入库**；
  3. A6/A7 复用文件导入与系统 share intent（`CaptureAcquisitionLaunchers` 族扩展）；
  4. B5 题级去重：录入时题面指纹比对（复用材料层指纹思路）；
  5. C11：错题行加收藏位 + 筛选 facet。
- **关键决策**：切分准确率门数值（立项时自定）；分享进 App 的目标路由。
- **验收门**：整卷切题真机走通且准确率达门；题级去重生效（主线 4C 行）。

## 4D · 图像净化与几何重绘【R1，大型】

- **需求**：B7 几何图/示意图**识别后重绘为规范图**（用户标"着急、核心、早有要求"）；A10 去手写、
  还原空白题干卷；A11 裁边/透视矫正/黑白化；B4 涂抹擦除（仅作识别扫错补救）。提取路线已裁：
  不做传统 OCR，多模态大模型提取。
- **现状证据**：`GENERATE_FIGURE` 已在（4B 批 1，REDRAW_PROBLEM/GENERATE_PROCESS）；
  转写管线（模型转写干净题干）与图像资产持久化（4B A2）已落地；`OpenAiEditsClient`（images-edits
  客户端）在退役的 `tools/image-mcp-server` 里，能力可并回 App；识别→重绘链路**未通**。
- **大致实现方向**（核心已定，勿再改向）：
  1. **重绘 = 生图模型生成**（用户裁定核心，与 4B 裁定「错题本里的图是生图大模型 API 转写的
     干净原题图」同源；**不做**本地 OCR、不做本地矢量/模板重建）：
     - 链路：拍照原图 → 多模态模型提取（题干文字/公式 + 图形语义描述）→ **生图模型重绘
       规范图**（复用 4B A1 `GENERATE_FIGURE` 的 REDRAW 链路与 `AttachedImageGenerator`
       生成器）→ 干净图与干净题干合成进卷；
     - A10 去手写/还原空白题干卷：**生图模型的图像编辑（edits）能力**承担（能力并入 App 内
       管线，不复活独立 MCP 进程，4B-A5 精神保持）；
     - A11 裁边/透视矫正/黑白化：既有 image-pipeline 规格落地；B4 涂抹擦除为识别扫错补救 UI。
  2. **准确率门是防线**：生图模型画数学图形有细节/标注易错的外部风险提示（见文末来源），
     这正是红线"识别绝不能扫错"必须量化的原因——重绘结果过门才入库；重绘后做一次
     "图与题干几何标注一致性"的语义核对（防生图模型画错标注）；
  3. 生成结果走 4B A2 的 canonical 持久化 + 幂等缓存（同指纹不重复付费）。
- **关键决策**：识别/切分准确率门数值（立项时自定）；"规范图"样式标准（待定样张）；
  生图重绘后的语义核对方式（核对步骤，不改变"生图"本体）。
- **验收门**：识别准确率门先立后实施；重绘链路真机走通（主线 4D 行）。

## 6B · 可编辑文档导出【R7 的 B3 全套，大型子系统】

- **需求**：① .docx 可编辑导出；② App 内基础编辑（增删题/调序/改文字）；③ 智能体自然语言改卷
  （"去掉选择题/难度调低"，与组卷器联动）。
- **现状证据**：PDF 侧已有完整参数化排版（4B：`MistakePdfLayout` + `DeterministicMistakePdfRenderer`
  + 三链路预览/打印/保存）；`START_EXPORT` 白名单 payload 模式已立（B3）。
- **大致实现方向**（外部研究要点，2026-10-11）：
  1. **docx 生成走手写轻量 OOXML**（ZIP + `document.xml` 等 XML 部件，零第三方依赖、APK 零增量；
     POI/docx4j 在 Android 上 65K 方法数/JAXB 问题重——练习卷是简单线性文档，不需要复杂样式引擎）；
  2. **单一文档模型，两条渲染器**：抽出现有 PDF 渲染器的"文档模型"层（题块序列 + 布局参数），
     PDF 与 docx 两渲染器共用同一模型（避免两套排版逻辑分叉）；
  3. **App 内编辑 = 编辑结构化模型**，不做 docx 往返解析（增删题/调序/改文字直接改模型，
     保存时重渲染）；
  4. 智能体自然语言改卷 = 模型输出白名单动作（增/删/排序/参数），沿用 `START_EXPORT` payload
     白名单校验模式，**模型不得输出任意排版标记**；
  5. 交付走现有 `MistakePdfDelivery` 同构链路（SAF/分享/打印），MIME
     `application/vnd.openxmlformats-officedocument.wordprocessingml.document`。
- **关键决策**：编辑深度（模型层编辑、单向导出——建议，不做 docx 往返）；docx 渲染器的样式范围
  （练习卷模板最小集）。
- **验收门**：导出→编辑→改卷三链路真机走通（主线 6B 行）。

## 6C · 备份与恢复【R9，数据迁移级】

- **需求**：个性化整合备份包导出（数据库+图片+设置，内容可选）+ 导入换机恢复 + 回收站误删恢复；
  与裁决 21 调和（旧"数据隐私/存储"两屏删除不变，备份包入口新增挂设置）。
- **现状证据**：`BackupRepository`（core:domain）已存在；纯单机无账号（审计-D8：设备丢失即全丢）；
  `allowBackup=false` + `backup_rules` 在 manifest；4A 已移除 TRASHED（回收站需先核现状）。
- **大致实现方向**：
  1. 备份包 = 单文件（zip）：`database.sqlite` + 图像资产（canonical vault）+ 设置 JSON + 元数据
     （app 版本/schema 版本/内容版本戳）；
  2. 导出个性化选择：内容勾选（错题本/掌握库/会话/图片）；
  3. 恢复 = 校验元数据版本兼容 → 落库 → 全量重放/投影重建（复用投影重放机制）→ 完整性对拍；
  4. 回收站：软删 + 宽限期（沿用既有"可逆归档/孤儿 GC 宽限"纪律），先核 4A 后现状再设计；
  5. 入口挂设置栏（裁决 21 清单扩充一项）。
- **关键决策**：备份包版本兼容口径（跨 schema 版本恢复策略）；回收站宽限时长（待裁）。
- **验收门**：备份→恢复往返演练通过（含换机口径，主线 6C 行）。
