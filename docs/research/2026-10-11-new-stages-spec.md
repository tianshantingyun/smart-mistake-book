  调 `cleanRedraw.generateClean`（`OpenAiImageGenerationChannel` 走 `/v1/images/edits`，

  全程 fail-closed（`:663-679`；装配见 `SmartMistakeBookApplication.kt:358-379`）。退役 MCP
  里的 `OpenAiEditsClient` 本就是该 channel 的移植、src 已删，**不复活独立 MCP 进程**。
  **真正未通的是 B7**：几何图形语义提取（题干文字/公式 + 图形语义描述）→ 规范图重绘的语义链
   尚无；A10剩余工作为触发范围、AUD-09持久任务/故障续跑与准确率门，AUD-10覆盖内存和采样精度；沿用现通道。
- **大致实现方向**（核心已定，勿再改向）：
  1. **重绘 = 生图模型生成**（用户裁定核心，与 4B 裁定「错题本里的图是生图大模型 API 转写的
     干净原题图」同源；**不做**本地 OCR、不做本地矢量/模板重建）：
     - B7 链路：拍照原图 → 多模态模型提取（题干文字/公式 + 图形语义描述）→ **生图模型重绘
       规范图**（复用 4B A1 `GENERATE_FIGURE` 的 REDRAW 链路与 `AttachedImageGenerator`
       生成器）→ 干净图与干净题干合成进卷；
     - A10 去手写/还原空白题干卷：**已由 edits 干净图重绘链承担（链路已通，见现状证据）**，
       本阶段扩触发范围、持久续跑及质量门，补资源/采样验证；不新建管线、不复活 MCP（4B-A5 精神保持）；
     - A11 裁边/透视矫正/黑白化：既有 image-pipeline 规格落地；B4 涂抹擦除为识别扫错补救 UI。
  2. **准确率门是防线**：生图模型画数学图形有细节/标注易错的外部风险提示（见文末来源），
     这正是红线"识别绝不能扫错"必须量化的原因——重绘结果过门才入库；重绘后做一次
     "图与题干几何标注一致性"的语义核对（防生图模型画错标注）；
  3. 生成结果走 4B A2 的 canonical 持久化 + 幂等缓存（同指纹不重复付费）。
- **关键决策**：识别/**重绘**准确率门数值（立项时自定；**切分门归 4C，两套门不共用**）；
  "规范图"样式标准（待定样张）；生图重绘后的语义核对方式（核对步骤，不改变"生图"本体）。
- **验收门**：识别/重绘准确率门先立后实施；B7 语义重绘链路真机走通；A10 已通链按新门做触发
  范围回归走查（主线 4D 行）。

## 6B · 可编辑文档导出【R7 的 B3 全套，大型子系统】

- **需求**：① .docx 可编辑导出；② App 内基础编辑（增删题/调序/改文字）；③ 智能体自然语言改卷
  （"去掉选择题/难度调低"，与组卷器联动）；④ **G11 卷子分享出（微信/QQ/邮件，交付家族）**。
- **现状证据**：PDF侧已有保存/打开/ACTION_SEND分享和参数化排版；AUD-06缓存补修为本阶段前置（4B：`MistakePdfLayout` + `DeterministicMistakePdfRenderer`
  + 三链路预览/打印/保存）；`START_EXPORT` 白名单 payload 模式已立（B3）。
- **大致实现方向**（外部研究要点，2026-10-11）：
  1. **docx 生成走手写轻量 OOXML**（ZIP + `document.xml` 等 XML 部件，零第三方依赖、APK 零增量；
     POI/docx4j 在 Android 上 65K 方法数/JAXB 问题重——练习卷是简单线性文档，不需要复杂样式引擎）；
  2. **单一文档模型，两条渲染器**：抽出现有 PDF 渲染器的"文档模型"层（题块序列 + 布局参数），
     PDF 与 docx 两渲染器共用同一模型（避免两套排版逻辑分叉）；
  3. **App 内编辑 = 编辑结构化模型**，不做 docx 往返解析（增删题/调序/改文字直接改模型，
     保存时重渲染）；
  4. 智能体自然语言改卷 = 模型输出白名单动作（增/删/排序/参数），沿用 `START_EXPORT` payload
     白名单校验模式，**模型不得输出任意排版标记**；
  5. 交付走现有 `MistakePdfDelivery` 同构链路（SAF/分享/打印），MIME
     `application/vnd.openxmlformats-officedocument.wordprocessingml.document`；**G11的PDF系统分享已存在，docx分享扩展复用此链路**，docx/PDF 两种格式同批可达，不另建交付通道。
- **关键决策**：编辑深度（模型层编辑、单向导出——建议，不做 docx 往返）；docx 渲染器的样式范围
  （练习卷模板最小集）。
- **验收门**：导出→编辑→改卷三链路真机走通；**G11 分享出（微信/QQ/邮件）可用**（主线 6B 行）。
