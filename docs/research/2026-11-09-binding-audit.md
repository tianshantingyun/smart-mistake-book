## 0. 结论（每条都带本会话实测）

1. **D-1 的现行对象已经不是批次 9 的那个包。** 现行成品包（`core/data/src/main/resources/knowledge`，工作树对该目录 `git status` 为空、与 HEAD 一致；目录最后提交 `7683640d` / 2026-11-04 22:42）：**3,280 节点 / 64,853 材料 / 64,853 绑定 / 25 sidecar**；批次 9 round2 的 manifest 记的是 **59,008 绑定**、`release_dir = build/kb-staging`（`build/agent-batch9/d1/precision/round2/manifest.json`）。**59,008 ≠ 64,853 → 95.15% 不能继承到现行包。**（实测 `l1_probe.json`、`frame_probe.json`）
2. **批次 9 的 95.15% 在"单侧 95% 下界"口径下不过门。** 用仓内同一分层公式复算：点估计 **0.9515374**、SE **0.0143786**、双侧 CI **[0.9233559, 0.9797190]**，与 `round2/report.json` 逐位相同（`point_match/ci_match = true`）；单侧 Wald 下界 **0.9278867**，Wilson-on-n_eff 下界 **0.9220027**——**均 < 0.95**。批次 9 原文写的是"点估计 ≥0.95，过门"，并自标"非总体下界保证"（`docs/kb-batch9-2026-10-12.md:78`）；按本轮门定义，它**不是**门值。
3. **两轮之间的"改进"是噪声。** round1 **0.9367861** → round2 **0.9515374**，差 **+0.0147513**、`SE_diff = 0.0217121`、`z = 0.6794`、双侧 **p = 0.4969**。把 round2 的 +1.47pp 归因于改绑，没有统计依据。
4. **在批次 9 的观测率上，任何样本量都过不了门。** 按 round2 各层率等比放大样本（600→50,000），门值从 0.9350 只爬到 **0.9499**，仍 <0.95（`n_needed_at_round2_rates`）。**样本量不是杠杆，真值才是**：要让 0.9515 的下界达标，只有整层普查（方差为 0）才行。→ 修复必须先把点估计推到 ≈0.96 以上，抽样才有意义。
5. **现有抽样器在现行包上直接失败。** `python -I tools/kb_coverage/sample_binding_precision.py --out build/b50-research/sampler-probe` → **TRUE_EXIT=1**：薄料名单 `knowledge-production/node-material-gaps-2026-10-10.csv` 有 **11 行**解析不到当前包节点（例 `CHEMISTRY/焰色反应`、`MATH/数据线性变换的平均数与方差`），脚本按设计拒绝出数。G1-12 的前置动作是**重生成该名单或改两层口径**，不是直接抽。（`sampler_probe.log`）
6. **样本量需求（现行框、Wilson 单侧、MC 功效实测）**：真值 0.965 时，n=600 → **56%**、1,200 → **80%**、1,600 → **89%**、2,000 → **94%** 功效；真值 0.97 时分别为 **80% / 97% / 99% / 99.8%**。计划写的"≥1,200"在真值 0.965 时只有 80%（若按护栏分配 950/250 则 **74%**）；要 90% 把握需 **≈1,600**。
7. **小层会被大层遮住，必须加 per-layer 护栏。** 现行框 overfull 权重 **0.9706**、normal 仅 **0.0294**：normal 层真值掉 10pp，加权点估计只动 **−0.29pp**（`0.9700 → 0.9671`）。实测门值容忍度：overfull=0.97、n=1,600（1,300/300）时，**normal 真值低到 0.60 门仍通过**（下界 0.9507），到 0.50 才失败（0.9479）。→ 只报加权值等于放弃对 2.9% 层的约束。
8. **整群效应在本设计的实测值可忽略但必须声明。** round2 的 600 条落在 **551 个不同节点**（`m̄ = 1.089`，单节点最多 3 条），**16 条错误分布在 16 个不同节点**（零簇内聚集）。按 `deff = 1.05` 保守放大，门值只降 **0.029pp**（n=1200、p=0.9594：0.94895 → 0.94866）。
9. **计划里两处措辞会破坏门的统计效力，必须改**：①"按 rule-of-three 取 ≥1,200"——rule-of-three 给的是**零错误下限** 52（Wilson 单侧）/59（精确 CP 单侧），不是 1,200，1,200 的依据是**功效**；②"或直到下界达标"——这是**数据依赖停表**，两次查看各按 95% 名义，α 上界 **0.0975**，名义 95% 实质降到 ≥90%。
10. **错误项处置必须与门值解耦。** 用"改完再判同一批"去提门值，等于拿被选中修复的样本冒充概率样本。批次 9 的产出里能读出这条风险：round1 的 **26 条错误只有 2 条**落在 round2 样本内（两轮 slug 交集仅 **213/600**），**其余 24 条从未被复测**。
11. **本批 D-1 只能是 model-labeled，且批次 9 连 model id 都没记。** `round2/manifest.json` 的键里没有 model/prompt/judge 字段，`_judge/*.decisions.tsv` 只有 4 列（slug / YES-NO / 引文 / 建议节点）。→ 引用 95.15% 的任何文案都不得写"由某模型判定"，只能写"model-labeled，模型未记录"。

## 2. 分层设计

### 2.1 抽样单位与估量

- **单位 = 一条绑定**（material × 现绑节点）。理由：门的判据就是"这条绑定对不对"，节点不是判据对象；且现行包 **1 材料恰 1 绑定**（§1.1），绑定与材料一一对应，配对键 `material_slug` 唯一（统计器 `:118-143` 已强制）。
- **估量 = 全框绑定级精确率**（分母 64,853）。**不是**"节点级至少一错"，也**不是**"材料级"。
- 结论要能落到"这个包能不能自动落账"，所以分母必须是**会进包的全部绑定**，不允许只算超配层（那是 97.1% 不是 100%）。

### 2.2 层的定义（推荐：2 层 + 风险子层只做分诊）

| 层 | 定义 | 现行框 N | 处置 |
|---|---|---:|---|
| `overfull` | 现绑节点在 `overfull_nodes.csv`（节点内 >4 条材料） | 62,948 | 抽样 |
| `normal` | 其余 | 1,905 | 抽样（且**故意超配**，见 §2.5） |

- **不把风险子层（`weak_match × rank`）升成独立层**：`yes_le4` 只有 1,034 条，单层 n≈60 时 Wilson 半宽 ±11pp，无权作为门的一部分；它作为**分配权重**（高风险子层按 1.5–2 倍配额）比作为独立层更有效。
- **薄料层**：现行框下不存在（名单失效）。若按 §1.4(a) 重建，其规模预计仍在 ~300 条量级，**建议直接普查**（见 §2.4）——整层普查让该层方差归零，比抽 200 条更强且可解释。

### 2.3 抽样核：把"固定起点等距"换成"随机起点 + 哈希排序"

现状是 `floor(i*N/k)`，**起点恒为 0**，且按 `material_slug` 排序。审计抽样对系统选样的经典告诫是：**当框内单元存在与抽样间隔同周期的结构时，系统选样会产生系统性偏倚**（ISA 530 附录 4 关于 systematic selection 的"周期性"告诫；见 §7.3，检索摘要级）。

**本框实测**（本会话抽查 3 个 sidecar 的首个科目池）：按 slug 排序后，同一源文档前缀（`ext-<科目>-<10 位 hex>-`）**最多连续 6 条**；本设计的层内间隔 `k = 62,948/1,300 ≈ 48`。→ **"与间隔对齐的长周期段"在本框尚未观测到**，所以这是**预防**而不是已证实的偏倚。但现状有两个真问题：

1. **固定起点使偏倚不可被检测**：起点恒为 0 时，任何与排序相关的系统性差异都会以同一个方向进入样本，且**下一轮仍一样**；换成随机起点后，至少这一项偏差变成随机的。
2. **排序键与源文档邻接完全重合**：`material_slug` 前缀就是源文档 id，等距抽样等于"按源文档均匀取样"。若某些源文档整体质量偏低（同一本书/同一批 OCR），误差会按文档批次聚集，而层内只有 4 条风险子层标签可以观测到这一点。

**改法（两行，确定可复跑）**：

```text
seed   = sha256(pack_scope_sha256 + "|" + audit_id)[:16]        # 预注册，写进 manifest
order  = 层内按 sha256(seed + "|" + material_slug) 升序           # 打散源文档邻接
start  = int(sha256(seed + "|" + layer)[:8], 16) mod k            # 随机起点，落在第一个间隔内
idx_i  = (start + i*k) mod N,  i = 0..n_h-1                       # 系统选样，等概率
```

- **确定性**：同一 `seed` 永远同一批件（可被第三方重放）。
- **不引入 RNG 状态**：不用随机库，避免"这次结果不一样"。
- **与批次 9 的 600 条不可比**：换了核就是换了样本，**不得**把新旧样本合并（也见 §4.3）。这一点必须写进记录。

### 2.4 小层用普查，不用抽样

- `thin`（若重建，~300 条）：**普查**。338 条在批次 9 已被抽 200（59%），再抽 200 的边际信息极小；普查后该层方差 = 0，且**修复后该层的确切错误数可作常数并入**（§4.6）。
- `normal`（1,905 条）：**不普查**（1,905 条判定 ≈ 48 个 40 条判定件，成本高于收益），抽 300 条（15.7%），配合 §2.5 的护栏。
- `overfull`（62,948 条）：抽 1,300 条（2.1%）。

### 2.5 整群效应与遮罩：两个必须显式处理的偏差

**（a）整群**：抽样按绑定、但错误按节点聚集（节点定义错 → 该节点几十条一起错）。本设计的实测整群极小（`m̄ = 1.089`，16/16 错在不同节点），但**不能因为一次实测就免责**：

- 门值计算时把 `SE` 乘 `√deff`，`deff = 1.05` 作为**预注册允差**（不是实测值）。实测影响：n=1,200、p=0.9594 时 0.94895 → **0.94866**（−0.029pp），不改变任何一档结论。
- 报告里同时给 `m̄` 与"错误落在多少个不同节点"，作为下一轮是否要提高 deff 的依据。

**（b）遮罩**：现行框 `w_normal = 0.0294`。实测（`layer_masking_sensitivity`，基准 0.97）：

| 情形 | 加权点估计 | 变化 |
|---|---:|---:|
| overfull 掉 1pp | 0.9603 | −0.97pp |
| overfull 掉 10pp | 0.8729 | −9.71pp |
| normal 掉 1pp | 0.9697 | −0.03pp |
| normal 掉 10pp | 0.9671 | −0.29pp |

门判层面（overfull=0.97、n=1,600、1,300/300）：

| normal 真值 | 加权 p̂ | 门值（Wilson 单侧） | 判 |
|---:|---:|---:|---|
| 0.95 | 0.9694 | 0.9609 | 过 |
| 0.90 | 0.9679 | 0.9594 | 过 |
| 0.80 | 0.9650 | 0.9565 | 过 |

→ **只报加权值，等于允许 2.9% 的层烂到 60% 还过门。** 因此门必须带一条 per-layer 护栏：

> **G2（防遮罩）**：每个抽样层各自的 Wilson 单侧 95% 下界 ≥ 0.90。n_normal=300 时，这等价于要求该层真值 ≳0.928（`per_layer_guardrail["300"]`：p=0.93 → 0.9017 过；p=0.92 → 0.8903 不过）。

## 3. 样本量与门算术

### 3.1 口径：什么叫"Wilson 单侧 95% 下界"

Wilson 是**单个二项比例**的方法；分层加权估计不是单比例，必须给出桥接方式。本方案的写法（**唯一主判据，预注册**）：

```text
p̂ = Σ_h w_h · (k_h / n_h)                     # 分层加权点估计，w_h = N_h / N
Var(p̂) = Σ_h w_h² · p̂_h(1 − p̂_h)/n_h · FPC_h  # FPC_h = (N_h − n_h)/(N_h − 1)
n_eff = p̂(1 − p̂) / Var(p̂)                      # 折成等效样本量
门值 L = Wilson_lower(k = p̂·n_eff, n = n_eff, z = 1.6449)     # 单侧 95%
判据：L ≥ 0.95
```

- 该式在**按层规模比例分配**时恰好退化为 SRS 的 Wilson（`n_eff ≈ n`），所以解释成本低。
- 它比仓内统计器现在用的**分层 Wald 下界保守 0.08–0.23pp**（`wald_vs_wilson`：n=1,600/p=0.965 → Wald 0.95744 vs Wilson 0.95662，差 0.082pp；n=600/p=0.97 → 差 0.228pp）。**只报一个**，不两个都算再挑通过的那个（`docs/research/2026-11-03-kb-r10-small-n-eval-stats.md:294-295` 的纪律）。
- 现有 `binding_precision.py:76-100` 输出的是 Wald + FPC。**最小改动**：在它旁边加 `wilson_neff`（10 行）并把 `json_out` 里的 `weighted` 增补 `gate_lo`；不改 `wilson_interval`、不改判定件表头。

### 3.2 零错误门槛（澄清"rule of three"）

"至少 n 条全对，才能说下界 ≥0.95"：

| 方法 | 最小 n | 备注 |
|---|---:|---|
| Wilson 单侧（z=1.645） | **52** | `n/(n+z²) ≥ 0.95` ⇒ `n ≥ 19z²` |
| 精确 Clopper-Pearson 单侧 | **59** | `0.05^(1/n) ≥ 0.95` |
| Wilson 双侧（z=1.96） | 73 | 双侧口径 |
| 精确 CP 双侧 | 72 | `0.025^(1/n) ≥ 0.95` |

→ **rule-of-three 一类算术只能给出 52–73 这个"零错误地板"，给不出 1,200。** 1,200 的依据是下一节的"容错 + 功效"，计划里"按预期错误率与 rule-of-three 取 ≥1,200"这句在算术上不成立，应改写（§6）。

### 3.3 现行框上的设计前沿（Wilson 单侧，MC 功效 2,000 次）

按层规模比例分配（`frontier_current_frame`）：

| n | 分配（overfull+normal） | 过门所需最小 p̂ | 允许错误数 | 功效@0.96 | @0.965 | @0.97 |
|---:|---|---:|---:|---:|---:|---:|
| 600 | 582 + 18 | 0.9646 | 21 | 0.302 | 0.561 | 0.804 |
| 900 | 874 + 26 | 0.9619 | 34 | 0.415 | 0.710 | 0.928 |
| **1,200** | 1,165 + 35 | **0.9603** | 47 | 0.500 | **0.803** | 0.970 |
| 1,500 | 1,456 + 44 | 0.9593 | 61 | 0.588 | 0.889 | 0.991 |
| **1,600** | 1,553 + 47 | **0.9590** | 65 | 0.589 | **0.891** | 0.992 |
| 2,000 | 1,941 + 59 | 0.9580 | 83 | 0.660 | 0.943 | 0.998 |
| 3,000 | 2,912 + 88 | 0.9565 | 130 | 0.836 | 0.991 | 1.000 |

**读法**：n 从 600 翻到 1,200，阈值只从 0.9646 降到 0.9603（**0.43pp**），但真值 0.965 时的功效从 56% 拉到 80%。再翻到 1,600 只多 0.13pp 阈值、+9pp 功效。**这是典型的边际递减**：n 买的是"判得出的概率"，不是"更低的门槛"。

### 3.4 推荐设计：n = 1,600（overfull 1,300 + normal 300），固定样本、一次判读

（`guard_allocations`，同口径）

| 设计 | 分配 | 过门所需 p̂ | 允许错误 | 功效@0.965 | @0.97 | per-layer 护栏（normal n） |
|---|---|---:|---:|---:|---:|---|
| 比例 1,200 | 1,165 + 35 | 0.9603 | 47 | 0.803 | 0.970 | n=35，护栏无意义 |
| 1,200 护栏版 | 950 + 250 | 0.9613 | 46 | 0.743 | 0.931 | n=250，要求 ≳0.93 |
| 1,200 护栏版 | 900 + 300 | 0.9616 | 46 | 0.719 | 0.920 | n=300，要求 ≳0.928 |
| **1,600 护栏版（推荐）** | **1,300 + 300** | **0.9597** | **64** | **0.840** | **0.983** | n=300，要求 ≳0.928 |
| 1,600 护栏版 | 1,200 + 400 | 0.9601 | 63 | 0.818 | 0.976 | n=400，要求 ≳0.92 |

**为什么是 1,600 而不是 1,200**：

1. 计划的下限 1,200 在真值 0.965 时只有 **80%（比例分配）/ 74%（护栏分配）** 的把握——一次发版门用 74% 把握的试验去判，等于**预先接受 1/4 概率的"真值达标却判 FAIL"**。
2. 真值 0.97 时 1,200 已足够（97%），所以 **1,200 不是错，是"只对 0.97 以上有效"**。是否接受这个赌注，属于产品决策，不属于统计——必须写进 prereg 而不是事后解释。
3. 1,600 的代价：40 个判定件（40 条/件）+ 4 个双判件（10% = 160 条），共 **44 件**；对比 1,200 的 33 件，多 11 件。

**如果预算死锁在 1,200**：用 950/250，并在 prereg 里写明 `功效@0.965 = 74%、@0.97 = 93%`，且 **FAIL 就写 FAIL**，不得改成"再抽 400 条看看"（§3.5）。

### 3.5 "直到下界达标"必须删掉（数据依赖停表）

计划写"≥1,200 或直到下界达标"。"先看到 1,200 不够，再抽到 1,600 报第二个下界"是**两次检验**：

| 做法 | 名义 95% 的实际保证 |
|---|---|
| 固定 n，一次判读（推荐） | 95% |
| 两次查看，各按 z=1.645 | α 上界 `1−(1−0.05)² = 0.0975` ⇒ **≥90%** 失败 |
| 两次查看，各按 Bonferroni α/2=0.025（z=1.96） | 95% 保住，但每次更严 |
| 两次查看，OBF 型消耗（首查 z=2.576） | 95% 保住，首查更难通过 |

→ **只允许两种写法**：(i) 固定 n、一次判读；(ii) 预注册 group-sequential（Bonferroni 或 OBF），并把每次的名义临界值写死。**禁止**"看着没过就再加样"。

### 3.6 本设计**不能**证明什么（必须写进记录，不许外推）

1. **零关键错误 ≠ 总体零关键错误**。n=1,600 全对时，关键错误率单侧 95% 上界 = `1 − 0.05^(1/1600) = 0.187%` ⇒ 全框仍可能有 **≤121 条**关键错误（n=1,200 → ≤162；n=2,000 → ≤97）。"关键错误=0"是**跳闸器**，不是"总体为 0"的证明。
2. **真值 0.955 判不出来（实测，不是估计）**。n=1,600 时，真值 0.955 的过门概率只有 **23.3%**（比例分配）/ **20.1%**（1,300+300，各 2,000 次 MC）；真值 0.958 → 43.4% / 40.0%；真值 0.960 → 58.9% / 53.9%。即：真值只比门值高 0.5pp 时，**约 3/4 的轮次会判 FAIL**。这个 FAIL 只能读作"没有足够证据说 ≥0.95"，**不是**"证明 <0.95"。
3. **没有人类专家**。见 §5。
4. **判定噪声未计入**。Wilson 只覆盖抽样误差，不覆盖同一模型两次判定的不一致。批次 9 无重复判定数据（两轮交集 213 条但已过改绑），**κ 未知**；本批必须用 10% 双判补上，κ<0.60 时该轮判定不得用于门（§5.4）。

## 4. 错误项：回填 / 改绑 / 复核

### 4.1 处置词表（与仓内既有表对齐，不新造概念）

| 处置 | 含义 | 落表 / 执行器 | 机械约束 |
|---|---|---|---|
| `KEEP` | 现绑正确（含"措辞不同不算错"） | `binding_suspects_reviewed.csv`（豁免） | — |
| `REBIND` | 应改到**同科**另一既有节点 | `material_rebind.csv` → `rebind_materials.py --write` | 目标必存在、必须同科、不得等于现绑（`apply_rebind_verdicts.py:11-13`） |
| `MERGE` | 现绑节点应并入另一节点 | `point_merge.csv` → `merge_points.py` | 合并后材料随链改指 |
| `NEW_POINT` | 同科无既有落点，需拆点/新建 | `new_points.csv` → `finalize_new_points.py` | 需拆点提案 + 覆盖依赖；**不得在审计中途新建**（见 §4.3） |
| `DROP_MATERIAL` | 材料不含可归知识（`NONE` 口径） | 包级处置（撤料） | 数据契约要求 1 材料 ≥1 绑定，**删绑定不可行** |
| `KEEP_WITH_REASON` | 判定与复核分歧，维持现状 | 记录 + 理由 | 必须由复核员记录，不由原判定员自留 |
| `ESCALATE` | 无法判定（证据不足/OCR 缺失） | 复核清单 | **计为错误**（保守口径），不得从分母剔除 |

> **跨科错绑没有自动通道**：`apply_rebind_verdicts.py` 与 `apply_unbound_bindings.py:16` 都强制"同科"。现行包跨科绑定实测为 **0**（§1.1），所以本批不会遇到；但若下批出现，只能走 `DROP_MATERIAL` / 改科 / `NEW_POINT` 三条路，且**必须产品裁决**，不得静默改绑。

### 4.2 三步必须分开：先估计，再修复，再复核

```text
① 估计（as-is）：冻结包 sha + 框 → 抽样 → 判定 → 门值 L_pre
② 修复：对①里判错的每一条给 §4.1 的处置 → 落表 → 复核（100%）
③ 复测：若 L_pre < 0.95 → FAIL；修复后**重抽 fresh 样本**（新 seed）→ 新门值 L_post
```

**关键纪律**：`L_pre` 是门值，`L_post` 是下一版的门值。**两者不得混用，也不得用 ②之后重判 ① 的同批样本去替代 `L_pre`。**

### 4.3 为什么不能用"修复后重判同一批"提门值

设样本里 k 条错，你把这 k 条改对，再在同一批上重判，得到 `(n−k)/n` 的"精确率"——这个数**不是任何总体的估计**，它是"我选中要修的那些都被修好了"的同义反复。它的偏差恰好等于修复率，随修复力度上升而上升。

批次 9 的产出里能看出这条风险的现实形态：

- round2 是"改绑后"的读轮，但它的样本与 round1 只重叠 **213/600**；
- round1 的 26 条错误**只有 2 条**被 round2 复测，**24 条从未验证是否修好**；
- 因此 round2 的 0.9515 **既不是**"修复前总体"的估计（它换了大半样本），**也不是**"修复后总体"的估计（它没覆盖已修复项）——它只是另一个样本的 as-is 读数，而两个读数之差（+1.47pp）在统计上不显著（p=0.497）。

→ **正确做法**：修复与复测彻底分离。要么 `L_pre` 过门（此时修复只影响下一版），要么 FAIL 后重抽。

**唯一例外**：整层普查（§2.4 的 thin，或任何被普查的层）。普查层的错误经 100% 修复 + 复核 AGREE 后，该层错误数是**已知常数 0**，不是抽样估计，可以零方差并入下一版权重。记录里必须写"该层为普查 + 修复后常数"。

### 4.4 复核协议（谁能改、看什么、怎么处分歧）

| 项 | 规则 | 依据 |
|---|---|---|
| 复核范围 | **100% 的 `REBIND`/`MERGE`/`NEW_POINT`/`DROP_MATERIAL`/`ESCALATE`**（不是抽样）。本批预计 40–70 条，成本可承受 | 仓内先例：`binding-audit-sampling-2026-10-03.md:72`（37 条重结论全覆盖） |
| 复核员 | **不同会话**，未参与判定；**不看**原判定的结论与理由 | 同上 `:72`；r10 文档的"预注册主判据唯一"纪律 |
| 问法 | 拆成两问，分开记录：**(a) 现绑是否错？(b) 处置目标是否正确？** 不得用一句"改绑成立"同时回答 | 2026-10-03 报告 `:74` 的教训（方向成立但去向错） |
| 分歧 | 预注册：复核 DISAGREE 时——若复核认为"现绑其实正确"→ 该条退出错误计数；若只是"去向不对"→ **仍计错误**，只订正去向；无法裁 → `ESCALATE`，**计错误** | 同上 `:75` 的两类 DISAGREE 口径 |
| 记录 | 逐条 `AGREE/DISAGREE` + 引文；汇总 `AGREE/(AGREE+DISAGREE)`；分歧条目单列 | 同上 §3.3 |
| 禁止 | 原判定员改判自己的项；用复核结果回头改 `L_pre` | §4.3 |

### 4.5 复核之外的第三道：判定一致性（κ）

- 每层随机 **10%**（1,600 → 160 条）**双判**：第二个会话独立判定，**看不到第一个会话的结论**。
- 报告 Cohen's κ（YES/NO 二分类）。**预注册闸门：κ < 0.60 → 该轮判定不得用于门**，只能作探索；此时只能报"判定不可复现"，不能报门值。
- 目的不是让门更好看，而是给"model-labeled"一个可核的可靠性数字。批次 9 没有这个数（**κ 未知**），这是它不能被引用的实质原因之一。

### 4.6 修复后重测的最小可执行清单

1. 用新 `seed`（= 新包 scope sha + 新 audit id）重跑抽样核（§2.3），**与上一轮样本零合并**。
2. 修复后包 sha 必须变化且被记录；若包未变而声称"已修复"，直接判证据无效。
3. 上一轮 `ESCALATE` 项若仍未解决，**在新样本里照样按错误计**（不因"已登记"而豁免）。
4. 若某层已普查且全修，该层在新一轮按**常数**并入并在报告里标注。

### 5.4 模型判定的宽松偏差：用确定性规则对冲（不是靠"再想想"）

模型判"这条绑定对不对"的默认倾向是 KEEP（2026-10-03 报告的口径甚至明写"拿不准就 KEEP"）。这类宽松偏差**不能靠统计区间发现**（区间只覆盖抽样误差），只能靠协议设计对冲：

| # | 规则 | 它消灭的失败 |
|---|---|---|
| 1 | **先写"材料自身讲的主题"，再与现绑节点比对**（两步、顺序固定） | 锚定：看到 node 名就说"对" |
| 2 | **`UNSURE` 独立成一档，且计为错误** | 把"拿不准"折进 KEEP，系统性抬高精确率 |
| 3 | **引文必须是正文逐字子串**（机械校验） | 编造理由；引文与材料无关 |
| 4 | **`suggestion == 现绑` 的比例要报**（若 >90%，说明在复述而非判读） | 模型不做判断、直接附和 |
| 5 | **判定件隐藏 `layer` / `weak_match` / `rank` / 审计目的** | 层名与"这是审计"的提示改变判定阈值 |
| 6 | **每层 10% 双判 + κ 闸门（<0.60 不出门值）** | 判定不可复现却当证据用 |

第 4 条可直接从批次 9 的 `decisions.tsv` 算出基线（本轮未算，登记为开工项）。
