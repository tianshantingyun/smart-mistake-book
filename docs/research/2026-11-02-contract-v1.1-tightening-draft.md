## 2. 收紧条款正文（C-1 … C-10）

### C-1 广告门：单向前置，不接受任何半步

**拟并入**：契约 §9（启用门）。

**条款文本**：

> JS 进入 `availableMethods` 的前提是：准入清单（`docs/research/2026-10-26-batch-24-4e2-admission-checklist.md`）的 69 行全部满足、MVA-JS-STATIC 成立、且设备证据与当前源码快照绑定（证据记录的 APK/源快照必须与待发布提交一致）。六处广告面（能力快照、工具集、prompt、工具描述、native schema、协调器执行分支）必须同源同时变。只改 prompt/schema、只接引擎、只通静态子集中的任一半步，均不构成广告；不得以"先广告静态、交互以后再说"解释既有条款。

**收紧点**：把"全部行未过，JS 不进 `availableMethods`"从清单纪律升格为契约条款，并补"证据绑定当前源码快照"。

**消灭的失败**：广告面与执行面不一致（广告了但执行端回 `UNAVAILABLE`，或未广告但模型可伪造 method）；用旧设备绿轮给新源码背书。

**验收判据**：广告前逐行核对清单并落 E-file；`availableMethods` 的 diff 与六处广告面 diff 同在一批；负向断言"未达门时 JS 不在广告面"仍在树并通过。

### C-2 PDF `/AIGC`：含 AI 内容的导出必须带隐式标识，注入不得破坏原文件

**拟并入**：契约 §8（导出与资产）、§9（合规门）。

**条款文本**：

> 导出 PDF 满足任一条件即必须写入 Info 字典 `/AIGC` 条目：①页面含 AI 生成/编辑的图像；②页面含模型解析（`QuestionBlockProvenance.MODEL_DOCUMENT_PARSE`）产生的文本。不得以"图有显式图注"替代隐式标识。实现采用增量更新：保留原文件全部字节前缀，从尾部 `startxref` 解析最后 xref/trailer，追加 Info 对象与新 xref 段及带 `/Prev` 的 trailer，再写 `%%EOF`；不得整文件重写、不得丢弃既有 Title/Author 等 Info 字段。同一文件重复注入必须幂等（不产生第二份 Info）。畸形输入（非 `%PDF-` 头、缺 `startxref`、坏偏移、截断）必须 fail-closed 且有码拒绝，不得产出"看似成功"的未标注文件。

**收紧点**：从"登记为 open 的合规缺口"升格为导出前置判据；补增量语义、幂等与畸形拒绝。

**消灭的失败**：AI 图/模型解析文本无隐式标识；注入导致原 PDF 前缀被改写、既有 Info 丢失；二次注入产生双 Info；坏 PDF 被静默放过。

**验收判据**：字节级往返（`PdfRenderer` 可开、页数不变、Info 读回 `/AIGC`、原前缀完整）；四类畸形各有码拒绝；既有 Info 合并与二次注入幂等各一例。**判据设计以 WS1 落地后的实际 schema 为准，本文不预填字段名。**

### C-3 错因：只出候选，不自动落账；撤销不留半行

**拟并入**：契约新增"结构化错因"节（或 §8 数据模型下的子节）。

**条款文本**：

> 错因枚举固定为 `CONCEPTUAL` / `PROCEDURAL` / `CARELESS` / `MISIDENTIFICATION` 四类并使用稳定码（不得按 UI 文案派生码）。错因必须带证据（讲解 trace、自评、重做结果中至少一类），无证据的错因不得落账。提取器只产出候选，不直接写业务成功；自动落账必须同时满足阈值、置信与可撤销三个条件，且默认关闭。撤销必须原子完成（错因、关联 revision/link、派生索引同事务），不得留半行或孤儿关联。

**收紧点**：把"候选/落账/撤销"三段语义写成硬边界，避免提取器直接写账。

**消灭的失败**：模型或启发式直接改学生错因；撤销后残留关联行导致统计漂移；错因码随文案改动而漂移。

**验收判据**：候选不落账负向；阈值/置信/撤销三条件缺一不落账；撤销后行数与关联数归零（或回到撤销前快照）且无孤儿；四类枚举码快照测试。

### C-4 复习容量：目标可提取度 + 考试日配额 + 欠账追赶，且必须诚实预览

**拟并入**：契约新增"复习调度"节（与 5b 交付同批）。

**条款文本**：

> 复习调度以目标可提取度（默认按 90% 设计，最终取值待裁，见 §5 Q3）为主参数；每日配额由考试截止日反推（exam-date quota），不得用固定条数掩盖截止日压力。漏做日必须重平衡（missed days rebalance），重平衡后的配额仍受单日上限约束。无法排入的条目必须计入 `unschedulableCount` 并在预览中如实展示；不得用"已排入"文案掩盖不可调度条目。调度版本/参数变更必须使旧预览失效并可重算，不得沿用旧配额。

**收紧点**：把"诚实预览"从 UI 期望升格为数据侧必须产出的字段与语义。

**消灭的失败**：考前一天配额爆量；漏做后计划静默失真；不可调度条目被隐藏；旧配额在新参数下继续展示。

**验收判据**：quota/rebalance/上限三类用例；`unschedulableCount` 与预览字段同源；参数版本变更后预览失效。

### C-5 模型任务扩展：类型与提示词分层，schema 升级只增不破旧

**拟并入**：契约 §3（请求协议）、§7（路由与预算）。

### C-6 快照身份：内容身份 = db + wal，`-shm` 显式排除

**拟并入**：契约 §8.1 与 §9（替换 `:208` 现句）。

**条款文本**：

> "快照身份"指导出前后两次输入字节清单的摘要，输入 = 主库文件 + `-wal`；`-shm` 是只读导出会重建/改写的共享内存索引，**显式排除**，不得纳入身份。身份必须在导出前记录、导出后复核；输入在导出期间变化必须拒绝并先于写盘失败。身份只证明"输入字节一致"，不证明"SQLite 读事务实际读到的逻辑快照"；后者需要读事务钉住，不得由身份摘要冒充。

**收紧点**：把 KD-81 关闭裁定写回契约，并补"身份 ≠ 事务快照"的上限句。

**消灭的失败**：同主库不同 WAL 报同一身份；`-shm` 自指漂移；把字节身份宣传成事务级快照。

**验收判据**：同主库不同 WAL 必得不同身份；无 WAL 如实记录；导出期间输入变化拒绝；`-shm` 变化不改变身份。

### C-7 DrawOps V1.1 语义不得回退

**拟并入**：契约 §5（DrawOps V1.1 五条之后）。

**条款文本**：

> 下列五条为 V1.1 的封闭语义，后续批次不得以"兼容旧文档"为由回退：①生成侧两道门拒 stroke-only（`PAINTER_STROKE_WITHOUT_FILL`）；②拒奇数长度或 `<2` 的 dash（`PAINTER_DASH_ODD`）；③8 位色 alpha 取 `floor(colorA × op.alpha)`；④度量与回放 Paint flags 必须显式装配（平台默认 1283 不是 0），并进环境指纹；⑤`hitRegions` 可非空、只做数组与预算校验并透传，painter 不绘制、由交互层消费。回放侧对应门保留为兜底，不自愈；任何词表变更必须升版并两侧同改。

**收紧点**：把"已收口"变成"禁止回退"，并明确回放侧不自愈。

**消灭的失败**：后续批次为兼容旧文档静默恢复 stroke-only/奇数 dash/覆盖 alpha；用平台默认 flags 冒充显式 0。

**验收判据**：两侧负向矩阵仍在树并通过；生成门与回放门同词；词表变更伴随版本升级记录。

### C-8 预算耗尽只能降级，不能换方法重置

**拟并入**：契约 §4（预算）、§7（切换）。

**条款文本**：

> 每个逻辑操作的预算（Provider 派发 ≤6、累计源码 ≤128 KiB、新布局尝试 ≤6、累计 JS 阶段墙钟 ≤10 s、单份工具 payload 解码后 JSON ≤512 KiB、最终图 ≤2 份）按 `operationId` 累计，切换 method 不重置、不新开操作。任一预算耗尽时必须走文字降级并使用原派发余额终答，不得以新操作/新方法绕开预算，也不得静默失败。降级必须可归因（有界诊断），不得伪装成成功。

**收紧点**：把"不重置"从实现注记升格为契约；补"文字降级是唯一出口"。

**消灭的失败**：换方法重刷预算；预算耗尽后继续派发；降级被记成成功。

**验收判据**：同 operationId 换 method 计数不重置；第 7 次派发/第 3 份最终图拒绝；耗尽后终答位保留且无新派发。

### C-9 strictOffline：可重放，不可新生

**拟并入**：契约 §6（离线与恢复）。

**条款文本**：

> strictOffline 下禁止任何外部派发与获取新模型源码；已持久程序在 API/SDK/运行库兼容且本地执行未关闭时可重新布局、拖动、播放，且必须 0 Provider 派发。静态冷恢复优先读快照；版本未知或执行熔断时读兼容快照/预览/文字。任何文案不得把"离线可交互"表述为"离线能生成新讲解"。

**收紧点**：把"0 派发"写成可观测判据；把文案红线写进契约而非仅台账。

**消灭的失败**：离线路径偷偷外发；把重放宣传成新生。

**验收判据**：离线重放设备向量 + 0 派发观测位；文案 grep 负向。

### C-10 版本、清单与备份三处同源

**拟并入**：契约 §8（schema 与备份）。

**条款文本**：

> DB schema 版本、请求 schema 版本、备份机器清单（表数/裁剪顺序/CLOSURE 版本与前缀）与 `identityHash` 必须同源：`identityHash` 只能由带 KSP 的构建生成并回填，不得手写；迁移落地后必须重新生成 schema JSON、同步备份清单并重算 goldens，三处同值后才可验证。门禁验证必须绑定当前 schema 版本，不得用旧版本 JSON 得到"通过"。版本被并行工作占用时顺延，不覆盖他线迁移。

**验收判据**：schema JSON 版本 = 数据库常量 = 备份清单版本；identityHash 三处同值；旧版本 JSON 跑门必须失败。
