## 3. 逐步执行说明

### Step 0 · 先读守则（15 分钟）
读 `roadmap §0` 执行守则六条；读 `decision-ledger` 的 D1 修订（"内核结构不动、表示与数值重做"）
与 K3 登记。**产出**：确认自己理解"待裁值不得自行取值"与"动投影公式必 bump 版本"。

### Step 1 · 阶段 1 地基（先让进行中的会话收口）
按 `phasing` 阶段 1 行执行：K1 会话事实模型、D-K4 统一底层、Q3/Q5、权限三档。
**门**：旧行可读（迁移矩阵绿）、唯一槽不破。**注意**：另一会话可能正在做——先 `git status`
与 `git log` 确认边界，勿重复、勿冲突。

### Step 2 · 阶段 2 智能体面（可与 Step 1 并行，不阻塞算法线）
C1/C2 + 致命 6 + 严重 7 + 工具面泛化（按 `spec §2.2b` 与 `phasing` 阶段 2 行）。D-Q9 的
F1–F8 地基（提示层级、L2 封顶、两套数轴）在此阶段的 UI 侧做，算法侧依赖 Wave 1 的采集链。

### Step 3 · 3A 前裁决（阻塞点：不裁完不进 Wave 0）
逐项过两个清单，**每项给证据+推荐，用户逐条裁**：
- 阶段 0 研究的 9 项"必须补"（`mastery-mechanism-review §2.5`）；
- 路线图 §9 待裁 9 项（看答案语义 A/B、β-二项先验、MASTERED θ/ε、L2 γ、fuzz、FSRS-7、
  pretest 交叉等）。
**门**：全部有裁定记录落台账。

### Step 4 · Wave 0 地基（3A 首批）
按 `roadmap Wave 0`：Q2 投影回退/防降级（projection_archive）、Q4 指纹读时校验、Q1 版本清单、
Q5 常数注册表。**门**：降级写被拒 + archive 落库 + 权重表单源。

### Step 5 · Wave 1 数据质量与正确性
按 `roadmap Wave 1`：duration 毫秒化、展示时长采集、persistedAssistance 链（KF-02）、看答案
三连（KF-03/06，语义按 Step 3 裁定）、日序三源统一（P1）、银行家舍入（P10）。
**门**：坏数据不再进拟合集（对应用例全绿）。

### Step 6 · Wave 2 拟合可信
按 `roadmap Wave 2`：w20 全调用点接线、采纳门 + 400 硬门、w3 剔除、state 列/每日首条/
day_start、fsrs-optimizer 对齐三件（附录 B）。
**门**：合成数据恢复测试绿（参数能训回真值）。

### Step 7 · Wave 3 表示重做
按 `roadmap Wave 3`：β-二项 s/f 双计数 + Wilson 下界（附录公式）、删 legacy、前置硬过滤、
P5/P8/P9/P11。**门**：手算轨迹对照 + 全量重放一致 + 迁移矩阵绿；本波是最大版本 bump，
Wave 0 的 archive 在此第一次实战。

### Step 8 · Wave 4 规模化（3A 尾 + 3B，可与 Step 6/7 并行）
按 `roadmap Wave 4`：排程放大（S12–S16，先候选池预筛）→ 投影热路径（S1/S3/S4/S7/S10）→
KB 索引（S19）→ 3B（S5/S6/S8）。**门**：5000 候选基准 <1s、检索长尾消失（实测前标 UNVERIFIED）。

### Step 9 · Wave 5 监测与自动化（3C）
按 `roadmap Wave 5`：KF-29 监测管线 → KF-30/KF-07 → KF-31（**只有监测有真实数据后才开**）→
KF-32 改绑重放（3B）。**门**：监测有数据 + 自动重审达标后开启。

### Step 10 · 阶段 4/5/6/7（产品面收尾）
错题本 L1–L7、复习栏（判题限定 + 备注回响 + D-Q9 引导模式默认）、学习档案（插眼 4 视觉先问）、
设置/悬浮球、文档作废清单逐条执行 + 全量门禁 + Q4 迁移链重置（所有 schema 改动后最后做）。
**门**：全绿 + 文档世界一致。

### Step 11 · Wave X（内测后，条件触发）
进入条件：真实 `review_log` 可预测样本 ≥400 条。做：srs-benchmark 配方离线模拟（附录 A）、
门常数校准、先验选择、fuzz 决策、FSRS-7 评估、HLR 训练晋升。
**门**：每一项都基于真实数据出报告，再进下一项。

## 5. 注意事项（每次会话开工前过一遍）

1. **共享工作树**：另一会话直接向 main 提交；提交用显式文件列表；勿切分支、勿 amend/rebase。
2. **Mimosa 扫描**：本机扫描器长期 inconclusive（scanner_enobufs）——不得据此声称任何安全结论。
3. **Mimosa SQL 纪律**：所有 SQL 一律参数绑定。
4. **指纹/版本纪律**：见 roadmap §0，违反者返工。
5. **每步结束**：更新本文件与路线图的进度标记（在对应步骤后注日期+状态），让下一个模型
   不用重新摸。
