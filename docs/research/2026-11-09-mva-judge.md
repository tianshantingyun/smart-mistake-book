## 0. 结论摘要（先给可执行结论）

1. **本仓的 120 集是"算术精确事实"集，不是"像素审美"集。** 209 条 critical 事实里 87 条是 `numeric`，其中 81 条要求容差 ≤1e-6（76 条 1e-9、5 条 1e-6）；另有 6 条 critical `count` 期望 11–25 个元素（该大数区间共 9 条，3 条非 critical）。按 §4.2 的通道规则划分后，**94 条事实（其中 87 critical = 81 numeric + 6 count）只能由结构化产物核验（A 通道）**；**57/120 题至少含一条"像素不可核验的 critical 事实"，27/120 题的全部 critical 事实都是这一类**（§6.1–6.2 实测计数）。→ 在纯像素（IMAGE_MODEL 栅格）臂上，VLM 判官**无法核验这 87 条**；任何"VLM judge 证明像素臂关键错误=0"的表述都是假声明。
2. **协议的核心不是"选哪个判官"，是"抽取与判定分离"。** 仓内既有形状已经是这个形状：`produce_output_facts` 产出"图上事实" → `check_fact_expectations` 拿事实与夹具预期比对（`figure_eval_gate.py:642-672`、`:896-900`）。协议只需把 fake 的 `produce_output_facts`（`:273-285`）换成"结构化提取器（A）/ 盲转写提示词（B/C）"，**判官永远看不到预期值**。这一条同时回答 VisionQ 的"选对图给错理由"和 ChartJudgeBench 的 over-Accept。
3. **宽松偏差必须可测量，否则"对冲"是口号。** 定义 JLI（judge leniency index，宽松指数）= 在**已知注入 critical 错误**的产物上的接受率。仓内 `_corrupt`（`:287-303`）已经能对六类事实逐类注入（numeric×2.5、丢标签、保留禁写标签、反向、错序、计数+2）。用它建校准集：**任一 kind 的 critical false-accept > 0，该判官在该 kind 上不合格，该类改判 UNVERIFIED、不计合格**（fail-closed）。
4. **"关键错误=0"目前是恒真式，没有证据。** `critical_error_accepted` 在 `:980` 硬编码 `False`，因为确定性核验器 `accepted = not mismatches`（`:672`）——只要有任何 mismatch 就不接受，所以"接受了的 critical 错误"结构上永远是 0。Q-05 的第四门在 IMG 路径上会**无条件显示通过**。→ 必须有独立的关键错误登记表（§4.5、§8 第 6 项），否则该门不可引用。
5. **盲测当前不盲。** `task_id` 前缀直接编码组别：`BLD-PROPCOORD-` / `BLD-MECHPHASE-` / `BLD-FLOWFORM-` / `BLD-SRCREBLD-` / `BLD-DEHANDWR-` / `BLD-NATILLA-`（本轮实测六组前缀）。判官提示词若带 `task_id` 就同时泄露组别与图型。需匿名 ID 映射（加盐 sha，映射只进报告不进口）。仓内已有同向先例：`_build_frame` 明写"state 只带任务身份，**不带预期值/题面**"（`:549`）。
6. **n=120 只能支撑点估计门，不能支撑下界门。** 114/120（=0.95，刚好压线）的 Wilson 95% 下界是 **0.895 < 0.95**；只有 119/120（下界 0.9543）或 120/120（0.9690）才让下界过 0.95。每组 n=20 时，**20/20 的下界也只有 0.8389 < 0.90**——分组门在数学上不可能是下界门（§7 实算）。这不是改阈值，是**解释纪律**：门的结论按点估计写，区间只作描述。
7. **三篇各自只贡献一条不可替代的东西**（§1）：VisionQ 的 **criterion-conditioned**（把判据写进问题，按 criterion 报，不报总分；20 个判官上限 63.1% vs 随机 32.2%）；ChartJudgeBench 的**偏差清单**（positional bias、系统性 over-Accept、RL 训练模型更宽松）；GGBench 的**像素指标不可信**（高感知相似度会掩盖错交点/缺相切）与其 **Pass@1（可执行性）**——后者正是本仓"工程检查"的同构物。
8. **两臂现状不对等，协议必须分臂写。** IMG 臂 `evaluable=True`（`:742`）；JS 臂主运行时 `final_accepted` 恒 `False`、质量门 `_unevaluable_quality_gates()`（`:959-965`、`:1176-1182`），因为"RenderScene 产物到 `fact_expectations` 的提取/核验器不存在"（`README.md:82-84`，本轮实读）。→ 计划说的"JS/IMG 两臂跑图"，JS 侧今天只能产出 NOT_AVAILABLE/UNVERIFIED，不能产出合格样本。
9. **判分结论没有持久层载体。** `FigureGenerationAttemptEntity` 字段到 `:155` 止，本轮 grep `quality` 零命中（`core/database/.../entity/FigureGenerationEntities.kt:129-155`）。本批不提议 schema 变更：判分结论落 run 级报告 JSON，用 `freeze_manifest.json` 的 sha256 + 产物 sha256 双绑定（§4.6）。

### 1.4 三篇能拼出的、本仓真正需要的那一块

三篇都停在"判官不可靠，要先验证"。本仓需要的下一步是**把判官的职责压到最小**：只让它做**转写**（读出标签、方向、顺序、计数），把**比较与裁决**交给确定性代码。理由是三篇共同指向的：判官在被要求"下结论"时会被整体观感带走（VisionQ），会系统性说 Accept（ChartJudgeBench），会被人眼级别的相似度骗过（GGBench）；而在"照抄图上写了什么"这件事上，它的错误是**可校准、可枚举**的（漏读、多读、读错方向）。这就是 §4 的三通道设计。

设计 `:85-87` 已经把检查切成三条，本协议严格沿用，不合并：

| 3 呈现检查 | 手机/大字/读屏/屏幕与导出内容可读，表单原生可操作 | **E1 呈现缺陷**（标签重叠、字号、对比、导出错位） | 否（单列报告） |

一条必须写死的例外：设计 `:89` 明写"不能把 TeX 原文意外泄漏当合格公式"。TeX 原文泄漏**看起来**是呈现问题（本该渲染成公式却显示了源码），但设计把它定为**不合格公式**——所以公式类的 TeX 泄漏归 **E0-X（禁写内容残留）**，不归 E1。这是全仓唯一一条"呈现问题升级为图义问题"的明示例外，本协议不推广它，只照抄。

另一条推论：**E1 不得用于"抵消" E0**。图再好看也不能补方向错（设计 `:89` 原文："不能靠免责声明修正错误受力箭头"）。E1 只降可用性，不改合格判定；但 E1 若导致某条事实**读不出**，该事实按 **UNVERIFIED → 不计合格** 处理（"读不出 ≠ 合格"，fail-closed）。

## 3. 关键错误 taxonomy

### 3.1 定义

- **关键错误（E0）**：任务夹具中任一 `critical: true` 事实的核验不通过，或该事实被判官/提取器声明为通过而实际不通过（false accept）。120 题中 **120/120 题至少含 1 条 critical 事实**，**49/120 题的全部事实都是 critical**（本轮实测），所以"整题豁免"没有空间。
- **关键错误被接受（accepted critical error）**：系统把上述错误计为合格。这是 Q-05 第四门（=0）唯一计数的对象。
- **E0 的判定单位是"事实"不是"图"**：一题 1–3 条事实（均值 2.4），任一 critical 失败即整题不合格。

### 3.3 与 VisionQ 六轴、GGBench 四段的对照

## 4. VLM-as-judge 盲测协议

### 4.1 冻结、盲法与不可调项

| 项 | 规则 | 落点/依据 |
|---|---|---|
| 夹具冻结 | 每次运行前校验 `freeze_manifest.json` 的 sha256，不一致即 exit 2 | `figure_eval_gate.py:185-208`（已有） |
| 分母 | 只含 120 盲测；24 开发集不计入 | `README.md:33-34`；本轮实测 blind/dev `task_id` 交集 = **0** |
| 盲测不用于调判官 | 判官提示词、阈值口径、示例只在 **dev 24** 上定型；盲测跑完后**不得**据其结果改判官提示词（改则旧集转回归集，须换未见集） | 设计 `:91` 原文"盲测题不得用于调prompt"的判官版 |
| 判官看不到什么 | `task_id`、`group`/`group_name`、`figure_type`、`sample_category_4e`、`fact_expectations`、`review_source` | 新增；理由见 §0-5（ID 前缀泄组） |
| 判官看到什么 | `problem_statement` + 渲染产物（像素或结构化场景）+ 该题的**判据清单**（criterion 名，不含预期值） | VisionQ 盲法（隐藏方法名/标题/出处）+ 仓内 `_build_frame:549` 先例 |
| 匿名 ID | `anon_id = "T" + sha256(salt‖task_id)[:10]`，salt = run_seed；映射表只写进报告 | 新增 |
| 呈现顺序 | 成对题双序（A/B 与 B/A 各一次）；选项序按 seed 洗牌并记录 | VisionQ 7.0 pp last-option；CJB positional bias |
| 判官版本记录 | provider / model id / temperature / max tokens / 图像 DPI / 渲染器版本 / prompt sha256 全部入报告 | 无源可调时行为会漂；不记录就无法复现 |
| 判官与被判产物不同源 | 判官不得是生成该图的模型（工程判断，非文献结论） | 标注为工程约束 |

### 4.2 三通道判定（本协议的主干）

| 通道 | 谁做判定 | 允许的事实类型 | 判定方式 | 失败语义 |
|---|---|---|---|---|
| **A 结构化计算** | 代码 | 结构化产物可导出的一切事实 | 从 RenderScene/DrawOps（JS 臂）或 provider 结构化 sidecar（IMG 臂，若有）提取值 → `check_fact_expectations` 比对 | 硬失败，任何通道都不能翻案 |
| **B 抽取后代码比较** | 模型只做**转写**，代码做比较 | 图上印刷的标签、表格单元、标注数值；禁写内容的存在性 | 模型逐条报"图上出现的字符串/数值"→ 代码按 `kind` 比对 | 转写出错 = 该事实 UNVERIFIED（不计合格），不是"另找理由过" |
| **C 视觉判断** | 模型判断，双判一致才有效 | 方向、顺序、粗布局等**不可转写为字符串**的谓词 | 闭式问题（枚举/二元），双判官独立作答；不一致 = 未决 | 未决/弃答/无有效选项 = **不合格**（VisionQ："a request returning no valid option counts as incorrect"） |

**优先级**：A > B > C。A 失败 → 整题失败，B/C 的"通过"不能翻案（记一次 judge false accept）。C 永远不能把 A 的失败改判为合格。

**通道分配规则**（确定性、可复现，见 §6.2）：按 `kind` + 容差/期望值大小分派，规则写进派生文件 `judge_channel_map.json`（从冻结夹具确定性生成，带自己的 sha256；**不改 120 集本身**，所以 `freeze_manifest.json` 与本协议的 sha 校验都不受影响）：

```
numeric  tol <= 1e-6      -> A 只          （81 条，全 critical）
numeric  tol >= 0.01      -> A | B         （6 条：换算表印刷值，可 OCR 后比对）
label_set                 -> A | B         （96 条）
label_absent              -> A | B         （14 条：存在性判定）
direction                 -> A | C         （24 条）
ordering                  -> A | C         （16 条）
count    expected <= 6    -> A | B | C     （38 条）
count    expected >  6    -> A 只          （9 条，其中 6 critical）
```

**为什么 `numeric tol<=1e-6` 必须 A 只**：1e-9 的比值/坐标/换算要求算术精确；栅格上任何测量误差都比 1e-9 大几个数量级。这不是判官能力问题，是**信息不在像素里**。若该图恰好把数值印在标签上，那属于同一题的 `label_set` 事实（另有一条），不能拿来当 numeric 事实的证据。

### 4.3 问题构造（逐条对标 VisionQ）

| 规则 | 反例（禁止） | 正例（采用） | 依据 |
|---|---|---|---|
| 要求**测量值**，不要求**结论** | "比例是否为 1:1？" | "读出左右两段各自长度（或直接给比值）" | VisionQ：把 grounding 移进问题；CJB：over-Accept 的根源是问结论 |
| 一题一问一 criterion | "这张图合格吗？" | 每条事实一个闭式问题 | VisionQ：总分/整体偏好会奖励"选对图给错理由" |
| 枚举受限 | 自由文本 | `{up, down, along_incline_up, other}` / `{present, absent, unreadable}` | 让"弃答"可被识别（VisionQ：无有效选项计错） |
| 明确允许弃答 | 逼判官猜 | `unreadable` 是合法答案，但**计为不合格** | fail-closed；"读不出 ≠ 合格" |
| 不掺美观 | "图是否美观/清晰"混进事实表 | 美观只进 E1 表，单列报告 | 设计 `:85-87` 三检查分离 |
| 一次调用一题 | 每题每事实一次调用（成本爆炸） | 一题一次调用、返回结构化答案表（全部事实） | 预算可控（§4.6） |

### 4.4 判官资质校准（先校准，后盲测）

**目的**：把"宽松"从形容词变成数字。

1. **校准集**：用 dev 24（56 条事实 / 39 critical，六类 kind 齐：numeric 16、label_set 19、count 10、ordering 4、direction 4、label_absent 3；本轮实测），或另建独立校准集。用仓内 `_corrupt`（`:287-303`）对**校准集内每条 critical 事实**注入一次错误，得到"已知必错"的产物；再取未注入版本作"已知必对"。
2. **测三个量（逐 kind）**：
   - `false_accept` = 判官把注入错误判为正确的比例（**这就是 JLI**）；
   - `false_reject` = 把未注入判为错误的比例；
   - `last_option_rate` / 双序不一致率（位置偏差）。
3. **准入规则（fail-closed）**：某 kind 的 `false_accept > 0` → 该判官**在该 kind 上不合格**，该 kind 的 C/B 判定不可引用，只能走 A；若该 kind 无 A 可用 → 该事实 **UNVERIFIED**，该题不计合格。
4. **记录**：校准集 sha、注入清单、逐 kind 三率，全部入报告 `judge.calibration`。
5. **重校准触发**：换判官模型/版本、改提示词、改渲染分辨率、改通道规则，任一发生即重跑。

> 这一节是"宽松偏差对冲"的**唯一实证环节**。没有它，§5 的所有对冲都只是设计意图，不是证据。

**一条必须先说的限制（本轮读码得出）**：`_corrupt` 腐化的是**事实值**（`:287-303` 返回 Python 值），不是**图像**。所以：
- 对 **A 通道**（代码比较）与 **B 通道**（值级转写比对）可直接用——校准的就是比较器/转写链路；
- 对 **C 通道**（视觉判断）**不能直接用**：必须先有"把错误值渲染成一张图"的脚本（改场景参数 → 过 painter → 出栅格）。仓内 **没有这个脚本**（本轮 `grep -rin "png|PIL|matplotlib" tools/figure_eval/ --include=*.py` **零命中**；`README.md:74-86` 已知缺口也未列）。
- 结论：**C 通道在有该脚本之前不可入校，也不可入盲测**。这一条把"VLM judge 能不能用"收缩成一个具体前置件，而不是一句判断。

### 4.5 关键错误登记（替代 `:980` 的硬编码）

登记表 `critical_error_register`，每条 `{task_id, fact_key, kind, source, evidence_sha256, note}`，`source` 三值：

| source | 触发条件 | 处理 |
|---|---|---|
| `deterministic_mismatch` | A 通道比对失败且该事实 critical | 计数 +1；该题不合格 |
| `judge_false_accept` | 判官（B/C）声明通过，但 A 通道同一事实失败；或校准集上同类注入被接受 | 计数 +1；该题不合格；同时记入判官资质问题 |
| `unresolved_disagreement` | 双判官不一致 / 双序不一致 / 判官弃答且无 A 证据 | 计数 +1；该题不合格（PRD-09 :132"分歧未决不能计合格"） |

**门的读法**：`critical_errors_accepted_max = 0` 读的是**这张表被接受的条数，不是"核验器不接受所以恒 0"**。今天 `:980` 的写死值必须改成真实计数，否则该门不可引用（§0-4）。

| 项 | 规则 |

| `label_absent` | 14 | 14 | 禁写内容 1 条/题 | A\|B | 可（存在性），但漏读即误过 |

**像素臂的硬结论**：`81（numeric 精确）+ 9（大计数）= 90 条事实在栅格上不可核验，其中 critical 87 条`。落到题上：**57/120 题至少含一条这样的 critical 事实，27/120 题的全部 critical 事实都是这一类**。所以：

- IMG 臂的"关键错误=0"**不能**由像素判官独立证明；必须靠 provider 结构化 sidecar（当前无）或主会话正式裁定（属改门，超出本文件范围）。
- JS 臂结构性更优：RenderScene/DrawOps 天然是结构化产物，A 通道可覆盖全部 288 条——**但提取器不存在**（`README.md:82-84`），所以今天 JS 臂一条也判不了。
- 这不是 120 集的缺陷，是它**本来就为确定性判分设计**（容差 1e-9 是"模型给出结构化参数后算得准"的标准，不是"人眼量得准"的标准）。协议必须承认这一点，而不是用一个宽松判官假装能过。

## 7. 门与统计口径（不改阈值，只定解释）

### 7.1 Wilson 区间实算（本轮计算，`wilson_ci` 同式 `:692-700`）

| 观测 | 点估计 | Wilson 95% 区间 | 能否支撑"下界 ≥ 阈值" |
|---|---|---|---|
| 18/20（每组门 0.90 压线） | 0.9000 | [0.6990, 0.9721] | 否 |
| 19/20 | 0.9500 | [0.7639, 0.9911] | 否 |
| 20/20（组内全过） | 1.0000 | [0.8389, 1.0000] | **否**（0.8389 < 0.90） |
| 108/120（0.90 压线） | 0.9000 | [0.8333, 0.9419] | 否 |
| 114/120（0.95 压线） | 0.9500 | [0.8952, 0.9769] | 否 |
| 119/120 | 0.9917 | [0.9543, 0.9985] | 是 |
| 120/120 | 1.0000 | [0.9690, 1.0000] | 是 |

**解释纪律**：
- 门的结论按**点估计**写（原值不动）。
- 区间只作描述性统计，**不得**表述为"CI 下界 ≥ 阈值"除非观测到 119/120 及以上。
- **每组 n=20 在任何观测下都不可能给出 ≥0.90 的 95% 下界**（20/20 也只有 0.8389）。所以"每组 ≥90%"天然是点估计门；把它当下界门写会得到数学上不可满足的判据。这一条必须写进 G4 的门证据，否则复核方会按错误口径质询。

### 7.2 零事件的上界（"关键错误=0"能证明什么）

| 观测 | 分母 | 95% 单侧上界（零事件精确解 `1-0.05^(1/n)`） | 读法 |
|---|---|---|---|
| 0 次被接受 critical | 120 题 | **0.0247** | 真实"整题关键错误率"的 95% 上界约 2.5%——**不等于 0** |
| 0 次被接受 critical | 209 条 critical 事实 | **0.0142** | 单条 critical 事实错误率上界约 1.4% |

所以"关键错误=0"是一个**点要求**（本次运行没接受过），不是"错误率已被证明为 0"。报告必须并排写这两个数，不得只写"0"。这条与设计 `:91` "不能称120例证明全场景正确"同向。
