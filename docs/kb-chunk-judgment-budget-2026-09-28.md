### 6.2 门对照

- 增长因子 G = 3.57–4.16 → 学科扫描 1.25–1.99ms → 约 **4.5–8.3ms**（本机口径）；设备开销按 1–3× 估 → 高界 ≈ 25ms；相对今天的**增量 Δ ≤ ~21ms**。
- 融合 p95：本机现值 204ms（`kb-stage7-report-2026-09-28.md:64`）→ 高界 **204 + 21 ≈ 225ms < 250ms 门**（余量 ≥25ms）；健康主机 148ms → ≈169ms；p50 现值 78ms + ~15ms ≈ 93ms < 150ms 门。
- **尾部风险说明**：p95 是墙钟门，历史多轮实测每次恰有 7.5–25.6s 的单样本设备停顿族（`kb-vector-topic-decision.md:145-148`；`kb-stage3-report-2026-09-24.md:212-215` 同族），p95 的波动主要来自该族，与内容增长正交；扫描增量是平滑、小额的。若未来真机复测越门，预案已存在：dense 腿一行回退（`DenseRecallAssembly.ENABLED=false`，`kb-stage3-report-2026-09-24.md:196-197`）与门重定标需用户裁定（`kb-stage2-dense-spec.md:188-192`）——不许施工者自行抬门。
- **首用/冷启**（不进 p95，但属加载预算）：`firstOrder 1,036ms @ 17.2MB`（`kb-stage7-report-2026-09-28.md:65`）随资产体积线性 → `.vec` 61.4–71.5 MB 时约 **3.7–4.3s 一次性**（首次检索吸收；测试预热轮不计入 p95，`GoldenRetrievalInstrumentedTest.kt:138`）；模型件 62.4MB 不变。

## 7. overBudget 判定：**false**

逐条依据（"超预算要有明确依据，不凭感觉"）：

1. **p95 门**：现行融合门 = p95 ≤ 250ms（用户 2026-09-25 裁定 Q1，`GoldenRetrievalInstrumentedTest.kt:549-585`）。高界估算 ≈225ms < 250ms，余量 ≥25ms；纯词面 150ms 门不扫 dense、不受影响。**不超。**
2. **APK 分发规模**：+59.1–72.7 MB → ≈311–325 MB。历史裁定中没有 APK 总量的数字上限；用户 2026-09-23 已裁定"质量性能优先、预算放宽"（`docs/kb-vector-topic-decision.md:6,196`——原"≈30MB"预算字面作废），且本增长是内容侧车与别名资产的线性增长，不是新机制引入。**无被超的预算可指认。**
3. **增长方向**：任何收紧（节点 ≤4 条上限执行、别名形状通过率下降、SKIP 占比升高）都只会使各项增长下移——本估算取的是上界。
4. 触发条件写死：若真机重建后融合 p95 越 250ms 门，门会红（自动化），处置走既有预案（§6.2），届时重新判定——本报告不替未来真机数下结论。
