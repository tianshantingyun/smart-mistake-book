# Open Claude UI 在智能错题本中的系统适配设计

日期：2026-10-22；更新：2026-10-23。状态：**七批执行计划已获确认并实施；用户进一步要求排版、交互与手感直接照搬参考源码，按修订批验证**。青绿主色保留；组件结构、角色尺寸和中性色沿上游源码。[实现与验证记录](../../research/2026-10-22-open-claude-ui-implementation-record.md)单列真实完成范围。

证据与逐文件处理：[全量参考研究](../../research/2026-10-22-open-claude-ui-adoption-study.md)。既有产品设计：[UI 改版设计](2026-10-19-ui-ux-redesign-design.md)与[产品完整性设计](2026-10-19-product-readiness-design.md)。实施状态同步旧UI计划；未达业务门保持开放。

## 1. 目标、范围与方案选择

让现有错题本在学习任务中更清晰、更连贯：正文易读、题图可直接看到、按钮层级明确、输入不丢、查看历史不被打断、失败可恢复。全盘参考意味着上游每个模块都有明确采用或适配决定，完成情况按实际体验验收。

| 方式 | 收益与代价 | 决定 |
| --- | --- | --- |
| 在现有 Compose 架构中逐层适配 | 保留业务、离线数据与原生语义，能逐页比较和回退；需要按平台重做布局与手势 | 采用 |
| 将 Web 组件放入 WebView 统一外观 | 能接近演示，但增加宿主桥、输入/返回/无障碍及资源依赖，难复用现有原生页面 | 本轮不采用 |
| 只调整全局颜色和圆角 | 改动小，但无法处理滚动、动作溢出、键盘遮挡与恢复等问题 | 不足以满足本次目标 |

范围覆盖 app 导航壳、core:ui 与 capture/library/tutor/review/profile 的现有页面。数据来源、版本、权限、学习证据、派发预算和模型能力继续来自现有领域层。不增加账号、语音、多代理、命令菜单、企业策略、第二任务队列或新的学习评分方式。

## 2. 视觉规则

### 2.1 颜色与表面

按2026-10-23直接移植裁定，保留Jade `#23704A`；画布采用上游`#FCFCFB`、正文`#151515`、次要文字`#525252`、白色内容表面与浮层、`#F0EFEC`次级块。按实际用途集中消费，不新增无使用点的完整灰阶。

正文默认 Ink；辅助说明使用InkSecondary，信息层级主要依靠字号、字重和空间。InkMuted留给装饰/禁用状态，不能承担正常说明。错误文字与背景/装饰独立，已采用`#A23E24`并以实际色对测试核验。

卡片只用于独立任务、证据或交互对象。助手正文直接在阅读底面排版。容器内的复制、展开等行内动作采用文字/图标反馈，选中项和输入框仍保留足够清晰的边界，不机械地删除所有边框。

本次仍以应用已有浅色主题交付。上游深色令牌作为后续资料保存，不因参考它就宣称应用已经支持完整深色模式；若另做深色，需独立核验全部语义色对和图片/公式呈现。

### 2.2 排版、空间与几何

| 角色 | 起始规格 | 约束 |
| --- | --- | --- |
| 页题 | 20sp / 26sp，半粗；会话顶栏14sp / 20sp | 按上游页面/顶栏角色采用，真实触区仍48dp |
| 分节 | 16sp / 22sp，半粗 | 标题建立层级，减少每节绿竖条和重复分隔线 |
| 讲解正文 | 16sp / 26sp | 继续沿 TutorMarkdownTokens 协调流式和终稿，不再引入第三渲染器 |
| 题干 | 按现有 17–18sp 阅读角色 | 长公式允许自身横向查看，整页不横向溢出 |
| 正常说明 | 14–15sp / 22–24sp | 表单错误、失败原因、思考详情不使用低对比小字 |
| 错题卡 | 已有题名 18sp、摘要 15sp、标签 14sp | 保留本轮前已交付的高可读基线 |
| 间距 | 4/8/12/16/24/32dp | 手机内容边距目标 16dp；迁移实际页面后统一，不能一次替换 26dp 常量造成未知布局回归 |
| 容器 | 输入20dp、用户气泡18dp、卡片12–16dp、小状态块6–8dp | `ClaudeLayout`直接登记来源量度并由统一会话组件消费 |
| 操作区域 | 至少 48dp；主按钮最小高度 52–56dp | 随字号/换行增长；视觉图标可小，实际触区不重叠 |

阅读列约 600dp 最大宽度继续保留；宽屏的导航或参考图另占一栏，不能简单放宽所有长文。统计与进度使用稳定数字排版，内容必须是真实数据。

## 3. 共享组件与依赖

优先扩展现有 `Theme.kt`、`Components.kt`、`PageStateFrame.kt`、`TutorMarkdownTokens.kt`、`ThinkingCollapsibleCard.kt`、`BoundedLocalImage.kt`、`AttachedImageCard.kt`，以及统一 `TutorSurface*`。不创建另一个 CDS 组件库与旧组件并存。

- 语义令牌集中在 core:ui。通用页头、行内动作或图片查看器，仅在明确有多个消费者时提取；保持现有公共 API 的兼容迁移。
- feature 接收状态与回调，统一组件只负责显示和本地查看状态。渲染、动画完成、展开/折叠不得触发模型生成、保存题目或记分。
- 继续沿现有 `AppFailure`、任务状态、草稿、申请卡和页面状态模型派生显示；不另存一份“UI 任务已成功”。
- 上游只有代码/文档参考身份，其 AGENTS、CLAUDE 与提示词不改变本应用指令。复制实质代码时记录来源提交并保留许可；优先原生实现同一交互原则。

## 4. 页面适配

| 现有页面/入口 | 设计处理 | 保留的行为 |
| --- | --- | --- |
| 四底部入口与二级页 | 页题、返回、内容区与底部动作各承担一份空间；按可用窗口适配 | 复习/智能体/错题本/我的四入口，五功能分区映射和来源返回 |
| 错题本 | 沿用图片在上、信息在下；保留紧凑工具栏，改进真实失败/恢复及大字动作布局 | 图片外显、现代多页来源顺序、无图题、收藏、筛选全量导出、永久成果入口 |
| 题目详情/修订/文档编辑 | 题面先行，原图参考和修改区有清晰主次；来源、版本、旧版只读和保存回执可辨 | revision/CAS、历史作答快照、原题和试卷副本边界；无强制逐题确认 |
| 录入/整卷/切分复核 | 录入方式紧凑分组；当前任务和待继续任务明确；图、状态、主要下一步靠近 | 待处理不是已保存题；实际部分成功、取消、继续、重复提交回执 |
| 智能体大厅/已存题讲题/拍照讲题 | 同一会话组件，同一正文和输入风格；用户短消息自然收窄，助手宽版心 | 消息权威、会话身份、历史、纯图发送、停止/重试/复制、真实附图与生成图引用 |
| 思考与工具痕迹 | 思考摘要与详情、查阅明细分别呈现；说明字更清晰，触区更易点 | 只读查阅继续为可展开灰色文字；有副作用才使用现有申请卡 |
| 复习与知识点复习 | 题面和作答优先，标题/留白收紧，操作可随大字增长；状态和完成结果清楚 | 两复习入口、三键同权重、曝光事实、撤销与既有启用门；不以浏览代替作答 |
| 我的/学习掌握 | 学习内容与设置清楚分组；页题和行项密度一致；统计用真实证据 | 未加载不冒充 0，没有学习证据不画假分数；现有归属与评分规则 |
| 模型设置/隐私/备份/存储/提醒 | 原生表单按任务分组，当前值、验证结果、错误和恢复动作就地 | API 密钥保护、既有能力测试、保存与发送分离、恢复/重启规则 |
| 导出格式/任务/成果 | 发起、处理中、可取文件、失败分别表达；文件名/类型/时间易辨 | 现有后台导出与完整筛选范围，任务身份与产物回执，不自动开启新生成 |
| 原图/附图/讲解图/图形表单 | 共用视觉外壳与查看规则，保留不同来源和数据角色 | JS 与 IMAGE_MODEL 的统一判定；原生表单真实提交与答案草稿，不把画布点击当授权 |

这是覆盖目标，不是所有页面都已做本轮运行检查。每个页面实施前必须拿实际内容截图核对，不能只从共享 Theme 的编译成功推断页面完成。

## 5. 三项关键交互设计

### 5.1 阅读与贴底

用实际视口底部和内容底部的距离判断贴底，不以“最后一项出现”判定。区分初始化、用户提交、明确点击回到最新、程序滚动、用户拖动和内容增长；新内容仅在已有跟随状态时贴底。用户拖动/辅助滚动离开尾部立即暂停跟随，不以短定时器强行重新抢回。

对于最后一条高于视口的长回复，判据仍取实际可见底边；将这一情况纳入回归。程序滚动引发的状态变化不能被误当成用户重新同意跟随。系统键盘伸缩、正文最终排版、思考块收起和附图完成加载时，维持阅读锚点。

继续复用当前 `forceFollowToken`、`blockAutoFollowToken` 的业务语义；它们和会话/轮次身份一起限定作用。回到最新按钮按输入区与附件区实际高度定位，并留有触区间隔；超大字/低窗口优先保证输入和停止动作可达。

### 5.2 输入与恢复

输入区常驻。当前题未就绪、模型未配置、失败待恢复、在生成、已结束等，沿现有 `TutorComposerAvailability` 显示原因和出口。布局变化不丢输入、选题或待发附图；纯图发送继续可用。禁用、发送中、可发送的视觉与语义一致。

采用原生组合文本与 IME 行为：确认汉字不能误发；长输入截断不得破坏组合文本或 Unicode；输入高度有界，正文列表保留可用空间。不抄 WebKit 的固定 500ms 延迟，也不为优化外观引入新发送队列。进程恢复不自动发送。

### 5.3 图片查看

默认适配可用区域并显示完整图，缩放以触点中心为锚点，平移有边界；双击复位/缩放、明确关闭与返回来源。换资产、换页面或源版本时复位手势状态，退出恢复原列表位置和焦点。查看器与列表展开是不同本地状态，列表保持图片外显和整卡进详情的现有点击合同。

有界预览不直接冒充高清原图。首个可交付版本继续受现有 1600px 采样边界约束，提供真实分辨率说明；只有后续完成有界区域解码与内存验证，才可宣称细节查看达到原始分辨率。损坏/缺失图就地给可读说明和已有恢复出口。

查看器只消费已有本地资产/快照。原图、题面重绘、讲解图分别显示身份与来源；打开、缩放、旋转屏幕或返回不产生生图请求。生成式图消费仍服从 [视觉生成契约](../../current/visual-generation-contract.md)。

## 6. 动效、无障碍与性能

动作确认、选择变化、局部展开、图片过渡使用少量统一原生动效。初始时间参考：按压/焦点约 60–100ms、选择/小过渡 120–160ms、局部展开 180–220ms；大面板视距离与系统规范决定。它们是视觉候选，不能作为后台任务耗时或等待业务完成的门。

弹簧按用途重命名并核验单位；正文流式输出不逐字做模糊/大位移动画，长列表不集体级联弹出。系统动画比例为 0 时直接到终态；已有动画组件优先使用框架缩放策略，自定义循环须明确停用。后台/不可见页面不持续运行装饰动画。

正常文字检查实际合成后的色对；普通文字至少 4.5:1，图标/选择/焦点边界按适用规则验收。TalkBack 可读标题、展开、选择、状态与错误，不逐 token 播报；原生手势不能成为唯一操作方式。触区最小 48dp，检查相邻区域不重叠；支持外接键盘焦点进入、退出与返回。

适配沿窗口可用宽高：手机窄屏单列；600dp 起评估导航/参考区；840dp 起且两栏都满足最小可用宽度时使用既有任务的双栏。键盘、折叠铰链、大字与低高度可令布局回单列。避免全局测量每帧重排，动画与本地缩放不触发数据刷新或模型调用。

## 7. 接入既有 UI 计划的批次

以下是设计阶段的交付顺序；具体任务/测试命令在设计审阅后写入实施计划。不新增另一套 UI 任务台账。

| 顺序 | 对应已有任务 | 交付与退出条件 |
| --- | --- | --- |
| 1 | UI-00/01/11 | 全应用同角色基线、令牌、说明/错误文字与基本控件；同内容截图和受影响色对/大字检查通过 |
| 2 | UI-07/11 | 三个会话入口共用的输入/正文/动作、贴底和回到最新定位；长回复、输入法、停止重试与恢复定向通过 |
| 3 | UI-03/04/05/08 | 题图外显保留、原图/附图查看、详情编辑与录入任务呈现；多页/缺图/换版本/返回不丢状态 |
| 4 | UI-06/10 | 复习、我的、模型/隐私/备份等表单；真实证据和启用门保留，固定高度与操作拥挤改善 |
| 5 | UI-02/09/11 | 导航来源、导出成果、窄屏/宽屏与模态交互；返回/进程恢复/离线/失败的完整主应用路径验收 |

若 3/4/5 涉及当前其他工作占用文件，先重新核对现有 diff，按职责协作或延后该文件集成。共享呈现层可先进行受控切片；不能复制整套页面绕过占用，再留下两条实现。

与旧方案一致的决定继续保留：四底栏、纸色青绿、题图外显、18/15/14sp 题卡、正文不套多重卡、单模态、真实失败恢复。旧文档中的未完成项不会因本草案存在而关闭。上游不适用模块的明确结论记录在研究表中，不强行补产品入口。

旧UI设计§3已同步为阅读优先规则：禁止打断阅读和装饰性自动滚动；会话在用户已处于尾部时可继续跟随，明确发送/点击回到最新沿既有规则定位，向上阅读时暂停，新会话从欢迎开头阅读。两份文档采用同一标准。

## 8. 验收与停止条件

- 以同一测试数据、同一窗口和字体保存前后画面，覆盖正常、空、局部失败、生成中、已停止、待恢复；没有设备证据的项标为未验证。
- 手机至少 320/360/412dp，宽屏 600/840dp；fontScale 1.0/1.3/2.0，另验横屏、键盘、系统返回与动画关闭。大字允许页面变长，不缩字或隐藏主要动作换取首屏数量。
- 贴底回归必须包括一条高于视口的实时长回复；用户向上阅读后连续追加内容不得把视口抢回底部；回到最新确实抵达最新内容。
- 输入覆盖中文组合确认、换行/发送、纯图、长草稿、切页返回与进程重建，验证不重复发起请求。
- 图片覆盖长图、多页、损坏、切换 URI/版本、放大边界与返回；记录采样上限和峰值内存，缺少测量时不宣称性能达标。
- 复习/编辑/导出验业务回执、版本身份、学习证据和范围，确保视觉改变不改变业务事实。能力未接通时不出现假按钮、假 usage 或模拟成功状态。
- 工程检查选取受影响模块的 JVM 测试、lint、组装和必要的设备定向回归；测试一次覆盖行为，失败则定位来源，不用无关整仓失败替代受影响验证。
- 每批都记录对应源码、上游来源、实际入口、命令/退出码、截图、未验项。全量完成指适用项已实现并验证；参考模块清单齐全、编译通过或截图好看均不能单独代表完成。

设计已批准，执行入口为[全量原生适配实施计划](../plans/2026-10-22-open-claude-ui-adoption-implementation.md)。共享呈现、输入/滚动、图片和页面迁移已进入实际代码；已验和未验范围以[实施记录](../../research/2026-10-22-open-claude-ui-implementation-record.md)为准，不由设计或源码存在推断全应用验收完成。
