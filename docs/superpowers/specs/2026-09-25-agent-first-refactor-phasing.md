## 划分原则

1. **先收口未决，再动代码**——插眼清单里还有三件待裁定，未裁定不动对应代码。
2. **依赖驱动排序，不是"由表及里"**——地基（会话模型/统一底层）是一切栏的底座，先做。
3. **每阶段有独立出口门**——出口门过不了，不进入下一阶段。
4. **与另一会话共享工作树**：涉及 Room schema 的阶段必须与之协调（历史教训：
   并发构建污染 schema 导出）；知识库内容生产与本重构尽量错开表结构改动窗口。
5. **坐标系先于掌握库对外承重**（2026-10-19细化）：3D仍是阶段5真实数据启用硬门；契约就绪可先做受控研发/隔离测试。不能用空归属或隐藏UI隔离证据，完整重放仍派生KC。

## 顺序的刚性

- 1 → 2 刚性：智能体交互面重建依赖会话事实模型；颠倒顺序会把"唯一文本权威"和"两条订阅"绑在一起改，质量必降。
- 0.1 → 3A 刚性：掌握库机制研究是插眼 6 的硬门槛（用户点名"动工前必须研究"）。
- 3A → 3B 刚性：重放与结构手术必须骑在表示重做之后（换框架后再动结构，否则迁移两次）。
- 3B → 5 刚性：复习栏的判题限定与 hint/retry 接线都骑在掌握库投影上。
- 其余阶段可在其依赖满足后小幅并行（如 4 与 3B/3C 后半可并行），但**每次只并行一个**，共享工作树下不搞多线。
- **4A → 4C、4B → 4D（2026-10-11；2026-10-18接线修订）**：录入二期骑在录入统一上；B7/A10等生图分支消费4E.1共享判定/coordinator，已有4B图像API作为后端复用，不按用途固定方法。
