## 方案取舍

采用共享消息文档渲染和本地受控插图引用。保留现有 Markdown 正文与资产持久化形式，在段落之间插入经过本轮资产归属校验的图。

另外两种方案分别为把所有图继续堆在消息末尾，以及改造为全新的可任意执行 HTML/JS 的消息文档。前者无法解决图文对应问题，后者扩大协议与运行时改动范围，并与既有隔离执行链路重复。本方案接续现有资产和隔离执行体系。

## 一、独立组卷页面

### 入口与布局

错题本工具栏“导出”改为“组卷”，打开独立页面。页面分为“选题”和“已选”两个工作区，手机内用页签切换，宽屏可采用既有分栏组件。

选题区顶部为搜索和筛选。复用科目、板块、掌握程度、收藏、排序和时间条件，已选条件可删除。列表直接展示题图与题干，题图保持原比例，题干可展开。勾选区与题目查看区分离，避免查看图片时误选题。

底部固定展示“已选 N 题”和“调整卷面”。未选题时主操作禁用。筛选条件只改变候选列表，跨搜索、翻页与筛选保留已选题。重复点选同一题切换选择状态。

### 已选与后续操作

已选区按当前卷面顺序展示题目，支持移除和明确的上移、下移操作，题号连续更新。进入现有卷面编辑器时携带有序题目 ID。编辑器返回后保留选择、顺序和筛选位置，配置变更与可恢复的进程重建使用 SavedStateHandle 恢复。

导出前重新核对题目身份与版本。题目删除或暂不可用时逐项提示并允许移除，超过既有限额时展示具体数量。题面变化需要重新载入并预览，避免用户选题和实际打印内容失配。

详细答案继续复用已有有效解答、缺失部分由智能体补齐、用户预览确认的链路。今日纸质复习仍使用它原有的冻结题目集合和回传确认流程。

## 二、聊天正文与 Markdown

### 视觉层级

助手正文使用通栏阅读式布局，学生消息使用轻底色气泡。统一正文 16sp、约 26sp 行高，段落间距 12dp。大标题约 22sp，小标题约 18sp，中小标题约 16sp 加适度字重，标题前间距大于标题后间距。数值使用主题令牌并支持系统字体放大。

有序步骤保留真实编号与列表缩进，嵌套列表逐级区分。引用用细侧线与浅底色，长表格局部横向滚动，公式独立留白并能在窄屏阅读。加粗用于关键条件、判断与结论。正文可以选择和复制，代码块保留现有复制行为。

用同一套阅读组件覆盖大厅对话、题目讲解、追问、完整解法、交互题干、选项说明与提交反馈。小型按钮、状态文字保留控件排版。

### 输出规则

模型先直接回应问题。内容自然分段，一个段落处理一个主要意思。推导包含多个阶段时使用明确的步骤标题与有序结构，关键条件和结论适度加粗，重要公式单独成行。短回答保持简短，已有题意与结论无需反复复述。

保持提示、追问、答案揭示的现有权限边界，尚未允许揭示答案的交互仍只展示提示。每条模型讲解回复必须穿插具有教学意义的配图，图和图注均遵守同一答案揭示边界。

历史消息保留原文，通过块级渲染恢复已有 Markdown 层级。普通文字无法确定的语义重点由原文决定，前端按段落语法呈现。现有 HTML、链接和外部图片安全校验继续复用，检查数学比较式被误判为 HTML 的情况并定向修复。

### 流式与交互状态

完成块与尾块采用相同正文字体和行距，块使用消息内位置身份，处理重复段落和未闭合语法。已完成块保持稳定，结束时避免整篇重排动画。

用户停留底部时跟随新内容，上滑阅读时保持当前位置，并显示轻量的回到底部入口。复制、重试、停止等沿用现有消息操作。动效采用已经确认的短促反馈和柔和过渡，系统减少动画时直接切换。

## 三、图片和 JS 图的嵌入

### 本地引用协议

模型从生成工具结果中取得本地引用后，在相关段落后单独输出 `[[figure:本地引用]]`。它是受控文档占位符，由共享文档解析器识别为插图块。引用必须出现在单独的普通段落中，代码、引用示例和数学内容里的相同字符按原文处理。

工具结果提供可引用的准确标记。宿主只接受当前回复已授权资产或该消息已提交的视觉快照引用，校验题面版本和消息归属。任意 ID、远程 URL 和任意 JS 正文不能据此变成可执行内容。复制和回喂消息时转换为可读图号描述，避免暴露内部标记。

同一个资产首次引用时显示完整图，重复引用显示轻量“见图 N”定位。旧消息中没有位置标记的图仍按原有顺序在本轮正文后展示，每张展示一次。引用无效时显示简洁的不可用状态，其他文字正常阅读。

### 共同视觉形式

图片与 JS 快照共用插图框。图片默认展开，按原比例完整适配可用宽度，浅边界、克制背景和紧凑图注。学科图中的文字保持清晰，点击进入现有大图查看器并支持缩放，返回恢复阅读位置。

图号来自本地实际显示顺序，图注复用已校验的可访问描述或生成说明，并明确区分原题图与讲解图。模型未实际看过生成结果时，图注使用用途描述，避免虚构图中细节。

工具执行中在本轮显示真实“正在绘图”状态，最终引用到达后落在指定段落。加载本地资产、生成失败、缺失资产、失效快照分别显示对应状态。图片解码失败提供重新加载，重新生成只通过明确的用户操作进入现有生成链路。重组、翻页和回看历史复用已有产物。

### JS 的真实能力

JS 与生图模型继续使用同一个 FigureGeneration 方法选择机制和实际可用能力快照。转写、题面重建、讲解、插图等用途统一判断精确结构、参数关系、像素保真和实际能力。

JS 静态图通过已有 programId、snapshotId 和预览资产读取，呈现方式与普通图片一致。已保存矢量快照可通过现有绘制链重放。只有产物声明并实际支持参数交互时才展示控制项，控件名称、范围、当前值与图的变化对应。当前分支生产 JS 尚未装配，需要与后端收口结果核对并补齐真实适配，分别记录静态显示与交互执行的验证结果。

已保存图的查看优先读取快照。新 JS 执行复用现有隔离引擎、预算、生命周期与提交事务，避免建立第二套任意 WebView 执行器。渲染失败保留可读取的已保存快照，并提供针对实际失败的恢复操作。

## 四、提问和反馈卡片

问题卡由简短标题、独立题干、清楚的选项组成。卡片与讲解正文对齐，选项采用可换行的行布局和一致触控区域。提交等待、已作答、错误、提示、解析展开都明确可见。

选择或填写与提交分为两个动作。每张卡只承载一个问题，用户可以在提交前调整选择或内容，再点击“提交答案”。选择本身只更新界面草稿，提交成功后才记录作答与学习证据。提交中防止重复操作，失败时保留草稿并允许重试，成功后显示已提交状态与对应反馈。自由作答输入区与提交操作相邻，键盘出现时保持主要操作可达。

## 七、个性化回复与通用答案的内容边界

本节采纳用户在批准路径时补充的要求，优先于草案中的可选配图措辞。

### 个性化回复

回复根据当前问题、学生本轮作答、已授权的学习证据与对话上下文调整解释切入、用词、粒度和追问。正文与图片协同呈现学生当前需要理解的关系、过程或易错处。提示阶段的图只能帮助当前提示，不能通过标签、图注或图形提前揭示被限制的答案。

### 通用答案

导出的详细答案按冻结题面编写，可脱离本次对话独立阅读。完整呈现解题条件、步骤、适用方法、必要公式、结论与单位。其生成输入保持为题面、原题图和通用的输出规范，个人掌握记录、聊天片段与个性化称呼不进入通用答案缓存。

聊天回复与通用答案分别生成、分别缓存和分别确认。现有 DetailedSolutionInput 已采用冻结题面输入，沿用这一边界。聊天文本不能直接作为标准答案的来源。复用解答时核对题面基准、图像完整性与本轮图解要求。

### 必需图解的范围和完成门

每条模型生成的讲解回复、每道题的通用详细答案都至少包含一幅有效图解，并穿插在对应步骤附近。短讲解可采用简洁的关系图、步骤图、对照图或条件结构图。应用生成的加载、取消、错误等状态文案使用状态组件。

“有图”以宿主已保存、可解析并与当前题面或消息对应的资产为准。模型声明、占位文字与失败卡片都不计入有效配图。可以复用仍有效且确实服务当前解释的图，重复生成需要走现有显式重试、预算和幂等链路。

简单图解必须通过 JS 完成，生图模型不可用不能成为省略简单图解的理由。只有复杂图确实必须使用生图模型、且该方法真实不可用时，才允许省略，并向用户说明缺少哪张图、JS 无法满足的具体原因和模型不可用的事实。JS 执行失败、资产损坏或版本失配时保留文字草稿并显示图解尚未完成。缺图内容不能被标记为完整图文讲解，详细答案的确认导出保持禁用，并提供明确的补图或重试操作。模型不通过反复自动申请图片完成次数要求。

历史内容保持可阅读。历史纯文字答案在再次准备导出时进入补齐图解流程，原有解答保留为可复用内容。已有题目卷仍可按其既有条件导出。

## 八、配图的教学质量规范

每张图必须回答一个明确的教学问题，并对应一个具体段落或步骤。生成前明确教学目标、关键对象、对象之间的关系、必须保留的条件、标注、单位和禁止误导的地方。

- 数学图核对定义域、坐标轴、方向、刻度、关键点、比例与函数关系。图示比例被简化时提供必要说明。
- 物理图中的受力方向、运动方向、作用对象、单位和坐标约定与题意一致。尤其受力分析中的箭头方向必须真实表达方向，使用排版区分标签和相邻箭头。
- 生物、化学及关系图核对对象、层级、方向、数量或比例，图例与正文一致。
- 流程图、对照图和知识结构图必须表达条件、差异、因果或步骤关系，避免把段落截成图片充数。
- 图中标签简短清晰，长推导与复杂公式由正文承担。颜色为辅助编码，使用文字、线型或标记保证灰度打印仍可辨认。
- 图像适配手机阅读和答案打印，保留完整边界，避免文字重叠、细节过小、标签遮挡或切边。

JS 与生图模型执行同一份教学目标和语义约束，方法按准确结构、参数关系、像素保真需求与实际可用能力选择。两个方法共享完成门，切换方法需要明确策略和预算约束。

宿主能验证协议、引用归属、题面版本、资产完整性、必要标签以及可检查的结构约束。模型自检与人工预览负责语义正确性复核，系统不会把图像文件可读等同于学科结论已验证。未经过独立核对的内容继续如实标识。

## 九、内容与图解验收补充

- 同一道题用于不同学生时，聊天可以采用不同提示和讲解切入，通用答案使用同一题面基准与通用行文。
- 正文中至少一个有效插图块，步骤与图注有明确对应；复杂图仅在确需生图模型且该模型不可用时允许带原因省略。答案每题独立检查，整卷中某一题的图不能替其他题满足要求。
- 覆盖缺图、仅占位、失败、引用错题、图文步骤不对应和历史纯文字答案的处理。
- 对典型函数图、物理受力图、步骤关系图检查方向、标签、公式与最终答案一致。语义检查结果与技术完整性检查分别记录。

- 2026-11-08 用户进一步限定省略条件。JS 接入后承担简单绘图，只有确需生图模型的复杂图在该模型不可用时允许省略。规划与验收必须验证具体理由和实际能力，普通绘图失败进入恢复流程。


## 十、参考截图确认后的讲解呈现标准

2026-11-08 用户已逐项确认本节的范围、双方消息布局、单题卡片和显式提交方式。本节优先于此前单击选项提交的描述。

### 消息与阅读宽度

学生消息采用右侧紧凑气泡，短消息按内容收拢，长消息按屏幕宽度换行。助手讲解采用连续文档布局，手机两侧各约 16dp 阅读边距，正文、公式、插图与提问卡共用内容区宽度。身份标识位于正文上方，避免占用整列阅读空间。宽屏按可读行长限制内容列宽。

### 正文、公式与图解

正文统一 16sp 和约 26sp 行高，段落间距约 12dp，支持系统字体缩放。标题按层级区分，步骤标题清楚简短。加粗用于关键条件、判断和结论，正文按推理阶段自然分段。

独立公式居中留白，行内公式与文字基线协调。分数、上下标、括号及化学反应符号应正确排版。长公式提供局部横向阅读。结论的强调样式根据公式语义呈现。

配图放在解释该关系的步骤之后，默认完整展开，点击进入大图查看。图注位于图下。插图用轻边框和克制的背景组织，减少重复图标、折叠标题和重复操作。比例对比、函数区间、受力和关系图按照内容安排比例与标注，图中颜色、线型和文字共同表达含义。

图解与正文共同回答当前问题。函数图应包含实际曲线、区间、关键点和所解释的量，受力图的箭头对应实际方向，比例图明确分类与比值。模型按当前题面与教学目标编写程序，完整教学示例展示坐标投影、原生标注及面积，支持自由组合已有路径与标签。

### 单题卡片与提交

一张卡片承载一个现有问题，并独立提交。选择题使用整行单选，选中后允许调整，再点击“提交答案”。已有文字作答入口遵循填写后提交的规则。卡片采用轻边框、明确题干和充足触控区域，按钮与作答区域相邻。

未作答时提交按钮禁用，提交中显示真实状态并防重复，失败后保留草稿，成功后展示对应反馈。选中动作不产生学习证据。多张卡之间各自维护问题身份与状态。

### 展示与答案边界

提示阶段只展示当前允许呈现的正文和图。完整解法及其图解在对应解法展开后呈现。提交后的反馈接在问题之后，上滑阅读与返回图片查看时恢复位置，流式更新遵循当前阅读位置。

### 实施与验收

修改已有消息容器、共享 Markdown 与公式渲染、插图组件和单题提交界面，沿用已批准路径。使用真实原生页面核对宽度、段落层次、公式、图文顺序、单题提交和大字体。图像文件及协议通过验证后，继续分别记录学科内容检查结果。

## 十三、聊天动作、回复版本与阅读玻璃栏（2026-11-09，已获用户确认）

### 已通过逐项问答确定的规则

- 消息下方提供带复制图标的“复制”和带循环箭头的“重新生成”。复制成功短暂显示勾选与“已复制”。 复制取当前显示版本中可见的正文、题卡和已展示反馈，配图使用可读图注描述。

顶栏与底部输入区使用暖白、轻磨砂背景，青绿作为交互强调色。背景采样层和清晰的前景文字、图标分层绘制。以 Haze 1.7.2 的 hazeSource/hazeEffect 接入现有 Compose，限定采样和模糊到上下栏区域。Maven 发布元数据依赖 Kotlin 2.2.21、Compose 1.10.0，项目当前为 Kotlin 2.3.21、Compose UI 1.11.3，实施时通过实际编译与设备渲染确认。

- 向上滑动阅读时，上下栏平滑收紧。回到顶部时展开标题，点输入浮条时展开编辑区域。
- 展开后显示附件和交互模式入口，输入法组合、草稿与附件状态随收展保留。
