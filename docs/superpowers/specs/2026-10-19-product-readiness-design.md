# 产品闭环补缺设计

日期：2026-10-19。状态：本轮按用户“深度研究、解决问题、改写后续计划”的要求形成设计与计划，**新增验收目标尚未通过，已有在飞实现先复用核验**。依据：[研究报告](../../research/2026-10-19-product-readiness-research.md)。本设计修订后续处理顺序与边界，不将旧完成记录改成新能力已完成。

## 1. 目标与范围

高中学生能把一道题录入、修正、再次练习、撤销误点、导出并恢复；模型不可用时，本地内容仍可阅读、编辑和导出。模型用于需要理解/生成的工作，受宿主权限、版本与预算约束。JS和IMAGE_MODEL继续是同一生图能力的两种方法。

不增加账号、社交、完整Word往返编辑器、第二调度器或第二事件系统。既有自动录入方向不变，纠错可达不等于强制每题人工确认。四科支持边界、3D数值门、3C自动化许可、X合格样本门和原有三键权重不在本次改值。

## 2. 开发与启用分开

| 能力 | 开发与测试前置 | 真实数据启用前置 |
|---|---|---|
| 空态、手动建题、题面编辑、原生格式选择、备份修复 | 对应数据契约与现有模块可用 | 本能力跨层验收，不额外等待3D/阶段5/4E |
| 5a三键、判题限定、撤销 | PRD-02/03契约与迁移明确后，可用隔离测试库并行研发 | 3D全部硬门、PRD-02/03/05验收；不得在用户库试写 |
| 5b知识点卡片/预算 | 3E队列契约先定，实施时同文件单写者 | 3D硬门+3E+答案键/证据门 |
| 5c讲题与自动标注 | 只对其实际依赖开发，不改原自动化许可 | 3D硬门；自动化仍遵循D-1及裁定39，覆盖依赖D-4 |
| 4E统一静态生图 | WG公共底座/隔离工程 | 各后端工程门+PRD-09质量门；所有入口同策略 |
| 5B完整回收/自适应 | 既有阶段5/3E/4C依赖 | 原阶段门+PRD-02纠错链复用；不能把会话反馈当可信回灌 |

本轮只把原“阶段5不得开工”修订为“允许受控研发，真实数据启用挂起”。5a不额外等3E，5b才消费其队列。**不采用QUESTION_ONLY过渡证据体系**；空归属也不是隔离开关。未来若改变此决定，必须先证明增量、全量、改绑、恢复均不会使题级证据意外进入知识点投影。

## 3. 四种修改操作分别建模

| 用户行为 | 改变什么 | 不应产生的副作用 |
|---|---|---|
| 修改原题 | 同problem的新revision，保存原图/来源，显式差异与CAS | 覆盖旧作答快照、把导出副本变化反写原题 |
| 修正答案键/判分 | 新键版本与目标证据的纠正/撤销事实，重放派生状态 | 追加一个“答对”抵销原“答错”、删除原学生答案 |
| 撤销误点评分 | 指向该次submission的撤销/替代事实与会话位置更新 | 倒减一个总分、重复计数、抹除已经看到答案的曝光 |
| 编辑试卷副本 | 文档块/布局/图引用的新版本 | 自动改变原题、旧学习记录或既有已发布卷 |

所有写命令带稳定operation/submission身份、目标、expectedRevision或expectedKeyVersion。重复命令返回既有回执；目标版本不同显式冲突，不用新时间戳绕过幂等。

### 3.1 原题修订的失效范围

原题编辑复用不可变revision与canonical资产。纯排版/备注更改只更新受影响展示缓存；题干条件、选项、答案或图义改变时，让基于旧basis的未完成生成/判分结果失效，标记旧解析/图为旧版，下一次练习加载新版。历史卷与历史作答保留原快照。

涉及已有错误判分时，展示受影响记录并走答案键纠正命令；不把任意编辑等同于所有历史作答错误。原识别纠正可保留学习单元并按依据修复归属；改编成另一道题必须另存新题/学习单元，不能借revision把旧学习证据挂到不同题目。沿既有KF-32改绑重放规则，验明确纠错的归属变化；不因一般编辑就无条件重派生所有旧记录。对尚未完成分类的新revision显示处理中/未分类；不能冒用旧分类声称新条件已核验。

### 3.2 答案键来源与验证

答案键至少保存 item/basis、keyVersion、答案内容摘要、来源类型/引用、验证状态/方式。这里是拟增加的概念字段，实施时先映射既有snapshot字段，避免重复存同一事实。

状态区分：模型建议且未独立核验、依据明确且经适用校验、用户修正、被质疑/撤回、历史来源未知。不得因本地ID比较成功而把键升级为已验证；第二个模型同意也不自动成为独立证明。机器验证须覆盖同一题版本、选项映射与条件，不以同知识点材料的答案替代当前题答案。

首批采用保守准入：未核验或有争议的模型键可继续显示本轮反馈和讲解，但不新增数值掌握证据；学生原始答案与来源持久保留。已验证键走现有客观规则；用户更正保留用户来源，不能伪装机器金标。未来若引入未核验键的折价投影，另做校准和版本化，不在这里设置新权重。

不自动重判全部旧库，不自动将所有未核验反馈日后晋升。针对有明确题键关系的记录执行修复，无法可靠定位的历史数据列出影响未知，不按时间相邻猜配。

### 3.3 纠正、撤销与重放

扩展现有LearningLedgerEvent/outbox/projector：attempt目标复用AttemptCorrection；chat evidence新增有明确targetEvidenceId的纠正/撤销事件。撤销是**从有效证据集合排除**，不是把权重改零后继续推进记忆卡；先检验现有结构能否表达，不能表达就显式增加事件语义。

一个纠错操作事务内固定键版本、命令回执、受影响目标清单与重放待办；大量目标分块幂等处理，持久记录游标。纠正事件挂回原作答因果位置，保留真正发生时间，不将修复日当成新练习日。相同目标的最终有效替代按账本序列决定，禁止循环引用。纠正路径绕过“新增证据冷却/配额”的语义，但仍验目标所有权、版本、来源，不借纠错创造额外学习证据。

增量遇纠正必须触发正确范围的重放；完成前相关掌握/日程呈更新中，不能把旧状态当修复成功。补偿完成的projection checkpoint与回执对应，杀进程后从待办继续。会话反馈、题级日程、知识点状态、统计、训练样本有效视图共用同一有效证据口径；计数不能遗漏已撤销的错误记录。

### 3.4 基础复习

三键仍为“对/卡顿/错”对应Good/Hard/Again，无Easy；source=SELF_REPORTED，原档和辅助/曝光折扣分列。完成作答后提交学生自评并展示已存答案/解析；主动提前看答案按既有reveal语义，判定后正常展开不额外罚分。没有可信已存答案时如实提示，可自评/跳过/请求讲题，不能伪称自动判对。

AI判词是可选帮助或兜底，不是已保存题目完成复习的唯一出口。无Key、断网、401、429均不阻断已过启用门的本地三键/撤销。不同题版本、重复提交、重启、撤销后再评均核稳定身份。已曝光后的重评不能恢复为未辅助独立作答。

## 4. 原生入口与实际能力

原生导出与智能体建议共享ExportDraft/参数校验/渲染/任务/成果交付，入口范围由宿主各自绑定：原生明确选择，智能体只取本轮合法候选。格式、布局、题数、是否含答案在原生sheet可见；用户发起已有资产导出不需调用模型。

首装空态通往录入；有题无到期与无题分开。手动题真正支持无照片建题，复用USER_TRANSCRIPTION来源与草稿恢复。未实现的动作不在prompt/tool schema广告，执行端仍拒绝旧或伪造请求。动态“已实现且允许且依赖就绪”的能力快照不按栏目硬分工具面。

权限文案对齐现有TutorPermissionPolicy：NOTEBOOK_WRITE及本地动作按ASK；MASTERY_UPDATE/ADVISORY_WRITE按AUTO_VISIBLE，由宿主门验证，失败有理由。模型不得直接写数据库或指定任意掌握数值；不把“自动、可见、受约束的证据写入”误写成全面禁止。

## 5. 恢复与文件一致性

备份导出、预检和恢复共享有版本的预算策略，数据库条目按真实规模给受限预算，流式处理不整体读入内存。预检校验解压总量、条目数、实际长度/hash和剩余磁盘空间；恢复仍在验证完成后交换，失败不损坏原库。

快照首选独立连接执行受支持的VACUUM INTO，不长期租用Room写连接；与关闭/恢复有生命周期互斥。旧API的checkpoint+copy必须有实际全写者屏障、检查busy/log/checkpointed与时间预算；超时退出且清理临时文件。不能把任何VACUUM错误都吞掉后退回无锁复制。若无法覆盖API23大库，保留为阻断项，再验证增量Backup API的驱动/绑定可行性。

快照开始前先取得与资产GC删除互斥的备份保护，快照完成后从快照库枚举引用并建立定向pin，再释放全局GC保护；pin保持到复制校验结束。复用已有保护机制，普通新增写入可继续；取消/超时释放租约，不允许快照与引用保护之间出现空窗。DOCX图片有界读取后固定同一份字节用于hash和嵌入，不出现校验A却打包B；必需图校验失败不得静默省略。草稿恢复按持久版本与本地编辑序列合并，不能用晚到旧读覆盖新输入；未成功落盘要保留可重试状态。该竞态修复以复现为前置。

## 6. 统一生图的质量与启用

公共策略不变，参见[共享提示词](../../current/figure-generation-prompt-policy.md)。所有转写、净化、重绘、讲解、改编入口都采用同一判定；普通UI图表、已有图读取/格式转换不新增模型调用。

1. 工程检查：源码/场景/像素/协议/隔离/预算合规。
2. 图义检查：源条件、标注、单位、方向、比例、坐标与角色相容；结构检查不能代替此项。
3. 呈现检查：手机/大字/读屏/屏幕与导出内容可读，表单保持原生可操作。

六张截图转为回归题意：3:1与1:1长度关系；F-x端点与0到h/2阴影、功的解析预期；流程卡上下游关系；原生单选与理由提交；真实受力方向；x=0/h/2/h阶段位置。不能靠免责声明修正错误受力箭头，也不能把TeX原文意外泄漏当合格公式。

首批质量目标是**工程启用标准，尚未实测，非文献保证**：冻结120个盲测任务（6组各20，覆盖比例/坐标、力学/阶段、流程/公式、源图重建、去手写、自然插画；原生表单另验），开发集另设且不计入这120例；盲测题不得用于调prompt。每个受支持的Provider/协议组合独立报告：首次合格≥90%，原预算内最终合格≥95%，每组最终≥90%；关键题意错误被接受=0、越权/超预算/恢复重复外发=0。重复同一题只作稳定性观察，不算独立新样本；报分母、置信区间和评审来源，不能称120例证明全场景正确。若按盲测失败样例修prompt，旧集转回归集，启用判定须使用新的未见盲测集。

方法由模型自主选择，不用“必须选JS”的标签评分。另有可同时满足要求的配对任务检验两后端与双向切换，不用固定路由伪装选择能力。明确要图却NO_FIGURE、降级为文字或原图保留只算安全退路，不算生图成功。

延迟先按同一设备/网络/模型配置量测，首批目标：首张合格图p95≤30秒（JS路径）、≤120秒（IMAGE_MODEL路径）；记录总链耗时、取消与修复次数。它们是待验证目标，超标不隐改阈值；必须说明缩小能力或经新版本修订。外部派发仍最多6次且遵守终答预留；token/费用按真实返回和配置计，未知费用标未知，不写0。质量评测必须在显式预算清单内运行，不后台自发花费。

先完成“一张静态图→保存→重启→详情→PDF/DOCX”，再开放4E.2交互及4E.3复杂保真。先验一张纵向链不替代4E.1全入口WG接线；六类表现不是六套硬编码绘图器。

## 7. 交付与不确定性处理

[实施计划](../plans/2026-10-19-product-readiness-followup-plan.md)逐项指定修改位置和验收。文档同步不关闭KD、不勾软件完成；每项保持代码/模块命令/设备全链/真实质量四栏。对于草稿竞态与独立快照连接等未实测点，先跑定向反例；证据不支持就删除误报或重选实现，不做预防性大重构。
